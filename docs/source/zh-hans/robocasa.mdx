# RoboCasa365[[robocasa365]]

[RoboCasa365](https://robocasa.ai) 是一个大规模仿真框架，用于训练和基准测试执行日常厨房任务的**通用机器人（generalist robots）**。它基于 PandaOmron 12-DOF 移动机械臂（全向基座上的 Franka 机械臂），提供跨 2,500 个厨房环境、3,200+ 个对象资产和 600+ 小时人类演示数据的 365 个多样化操作任务。

- 论文：[RoboCasa: Large-Scale Simulation of Everyday Tasks for Generalist Robots](https://arxiv.org/abs/2406.02523)
- GitHub：[robocasa/robocasa](https://github.com/robocasa/robocasa)
- 项目网站：[robocasa.ai](https://robocasa.ai)
- 预训练策略（policy）：[`lerobot/smolvla_robocasa`](https://huggingface.co/lerobot/smolvla_robocasa)
- 单任务数据集（CloseFridge）：[`pepijn223/robocasa_CloseFridge`](https://huggingface.co/datasets/pepijn223/robocasa_CloseFridge)

## 可用任务[[available-tasks]]

RoboCasa365 将其 365 个任务组织为两个任务族和三个上游基准组（benchmark groups），LeRobot 将这些组作为一等 `--env.task` 快捷方式提供：

| 任务族 | 任务 | 描述                                          |
| ------ | ---- | --------------------------------------------- |
| 原子   | ~65  | 单技能任务：抓取放置、门/抽屉操作、电器控制   |
| 复合   | ~300 | 跨 60+ 个类别的多步骤任务：烹饪、清洁、整理等 |

**原子任务示例：** `CloseFridge`、`OpenDrawer`、`OpenCabinet`、`TurnOnMicrowave`、`TurnOffStove`、`NavigateKitchen`、`PickPlaceCounterToStove`。

**复合任务类别：** 烘焙、煮沸、冲泡、切剁、清理桌面、解冻食物、装载洗碗机、泡茶、用微波炉加热食物、洗碗等。

`--env.task` 接受三种形式：

- 单个任务名称（`CloseFridge`）
- 逗号分隔的列表（`CloseFridge,OpenBlenderLid,PickPlaceCoffee`）
- 基准组快捷方式——`atomic_seen`、`composite_seen`、`composite_unseen`、`pretrain50`、`pretrain100`、`pretrain200`、`pretrain300`——它会自动展开为上游任务列表，并自动设置数据集的 `split`（`target` 或 `pretrain`）。

## 安装[[installation]]

RoboCasa 及其依赖项 `robosuite` 未发布在 PyPI 上，而且 RoboCasa 自身的 `setup.py` 硬编码了 `lerobot==0.3.3`，这与本仓库的 `lerobot` 冲突。因此，LeRobot **不**提供 `robocasa` extra——请以可编辑克隆的方式手动安装这两个包（在 `robocasa` 上使用 `--no-deps`，以跳过其被遮蔽的 `lerobot` 版本固定）：

```bash
# 在按照标准 LeRobot 安装说明操作之后。

git clone https://github.com/robocasa/robocasa.git ~/robocasa
git clone https://github.com/ARISE-Initiative/robosuite.git ~/robosuite
pip install -e ~/robocasa --no-deps
pip install -e ~/robosuite

# Robocasa 的运行时依赖（即其 setup.py 原本会拉取的依赖，但不包括
# 错误的 lerobot 版本固定）。
pip install numpy numba scipy mujoco pygame Pillow opencv-python \
            pyyaml pynput tqdm termcolor imageio h5py lxml hidapi \
            tianshou gymnasium

python -m robocasa.scripts.setup_macros
# 轻量级资产（lightwheel 对象网格 + 纹理）。足以
# 开箱即用地支持默认环境。
python -m robocasa.scripts.download_kitchen_assets \
  --type tex tex_generative fixtures_lw objs_lw
# 可选：完整的 objaverse/aigen 注册表（约 30GB），以获得更丰富的对象
# 多样性。评估时通过 --env.obj_registries 启用（见下文）。
# python -m robocasa.scripts.download_kitchen_assets --type objs_objaverse
```

<Tip>
RoboCasa 需要 MuJoCo。请在训练或评估之前设置渲染后端：

```bash
export MUJOCO_GL=egl  # 用于无头服务器（HPC、云）
```

</Tip>

### 对象注册表[[object-registries]]

默认情况下，环境仅从 `lightwheel` 注册表（registry）采样对象（即 `--type objs_lw` 提供的对象），这可在磁盘上没有 objaverse / aigen 包时避免 `Probabilities contain NaN` 崩溃。如果你已下载完整资产集，可在运行时启用完整注册表：

```bash
--env.obj_registries='[objaverse,lightwheel]'
```

## 评估[[evaluation]]

下面所有评估代码片段都与 CI 命令一致（参见 `.github/workflows/benchmark_tests.yml`）。`--rename_map` 参数会将 RoboCasa 的原生相机键（`robot0_agentview_left` / `robot0_eye_in_hand` / `robot0_agentview_right`）映射到已发布的 `smolvla_robocasa` 策略（policy）训练时所用的三相机（`camera1` / `camera2` / `camera3`）输入布局。

默认情况下，每个任务使用 RoboCasa 注册的 rollout 时域。设置 `--env.episode_length=<steps>` 可将相同的显式时域应用到每个选中的任务。

### 单任务评估（建议用于快速迭代）[[single-task-evaluation-recommended-for-quick-iteration]]

```bash
lerobot-eval \
  --policy.path=lerobot/smolvla_robocasa \
  --env.type=robocasa \
  --env.task=CloseFridge \
  --eval.batch_size=1 \
  --eval.n_episodes=20 \
  --eval.use_async_envs=false \
  --policy.device=cuda \
  '--rename_map={"observation.images.robot0_agentview_left": "observation.images.camera1", "observation.images.robot0_eye_in_hand": "observation.images.camera2", "observation.images.robot0_agentview_right": "observation.images.camera3"}'
```

### 多任务评估[[multi-task-evaluation]]

传入以逗号分隔的任务列表：

```bash
lerobot-eval \
  --policy.path=lerobot/smolvla_robocasa \
  --env.type=robocasa \
  --env.task=CloseFridge,OpenCabinet,OpenDrawer,TurnOnMicrowave,TurnOffStove \
  --eval.batch_size=1 \
  --eval.n_episodes=20 \
  --eval.use_async_envs=false \
  --policy.device=cuda \
  '--rename_map={"observation.images.robot0_agentview_left": "observation.images.camera1", "observation.images.robot0_eye_in_hand": "observation.images.camera2", "observation.images.robot0_agentview_right": "observation.images.camera3"}'
```

### 基准组评估[[benchmark-group-evaluation]]

运行整个上游组（例如所有 18 个 `atomic_seen` 任务，且 `split=target`）：

```bash
lerobot-eval \
  --policy.path=lerobot/smolvla_robocasa \
  --env.type=robocasa \
  --env.task=atomic_seen \
  --eval.batch_size=1 \
  --eval.n_episodes=20 \
  --eval.use_async_envs=false \
  --policy.device=cuda \
  '--rename_map={"observation.images.robot0_agentview_left": "observation.images.camera1", "observation.images.robot0_eye_in_hand": "observation.images.camera2", "observation.images.robot0_agentview_right": "observation.images.camera3"}'
```

### 建议的评估回合数[[recommended-evaluation-episodes]]

**每个任务 20 个回合**，以实现可复现的基准测试。与已发布结果中使用的协议一致。

## 策略输入与输出[[policy-inputs-and-outputs]]

**观测**（Observations，原始 RoboCasa 相机名称保持不变）：

- `observation.state` — 16 维本体感知状态（基座位置、基座四元数、相对末端执行器（end-effector）位置、相对末端执行器四元数、夹爪 qpos）
- `observation.images.robot0_agentview_left` — 左智能体视角，256×256 HWC uint8
- `observation.images.robot0_eye_in_hand` — 腕部相机视角，256×256 HWC uint8
- `observation.images.robot0_agentview_right` — 右智能体视角，256×256 HWC uint8

**动作：**

- 在 `Box(-1, 1, shape=(12,))` 中进行连续控制——基座运动（4D）+ 控制模式（1D）+ 末端执行器（end-effector）位置（3D）+ 末端执行器旋转（3D）+ 夹爪（1D）。

## 训练[[training]]

### 单任务示例[[single-task-example]]

Hub 上有一个可直接使用的单任务数据集：
[`pepijn223/robocasa_CloseFridge`](https://huggingface.co/datasets/pepijn223/robocasa_CloseFridge)。

在 `CloseFridge` 上微调 SmolVLA 基础模型：

```bash
lerobot-train \
  --policy.type=smolvla \
  --policy.repo_id=${HF_USER}/smolvla_robocasa_CloseFridge \
  --policy.load_vlm_weights=true \
  --policy.push_to_hub=true \
  --dataset.repo_id=pepijn223/robocasa_CloseFridge \
  --env.type=robocasa \
  --env.task=CloseFridge \
  --output_dir=./outputs/smolvla_robocasa_CloseFridge \
  --steps=100000 \
  --batch_size=4 \
  --env_eval_freq=5000 \
  --eval.batch_size=1 \
  --eval.n_episodes=5 \
  --save_freq=10000
```

评估生成的检查点：

```bash
lerobot-eval \
  --policy.path=${HF_USER}/smolvla_robocasa_CloseFridge \
  --env.type=robocasa \
  --env.task=CloseFridge \
  --eval.batch_size=1 \
  --eval.n_episodes=20
```

## 复现已发布结果[[reproducing-published-results]]

已发布的检查点 [`lerobot/smolvla_robocasa`](https://huggingface.co/lerobot/smolvla_robocasa) 使用[评估](#evaluation)部分中的命令进行评估。CI 会在每个涉及该基准测试的 PR 上运行一个包含 10 个原子任务的冒烟评估（每个任务一个回合），并选择那些以固定装置为中心且不需要 objaverse 资产包的任务。
