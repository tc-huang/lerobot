# Unitree G1[[unitree-g1]]

<img
  src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobot/unitree_thumbnail.jpg"
  alt="Unitree G1 移动操作演示"
  style={{ width: "100%" }}
/>

Unitree G1 人形机器人现已获得 LeRobot 支持！你可以对其进行遥操作（teleoperation）、训练移动操作（locomanipulation）策略（policy）、在仿真（sim）中测试等。29 和 23 自由度（DoF）版本均受支持。

---

## 第 1 部分：快速开始[[part-1-getting-started]]

### 安装 Unitree SDK[[install-the-unitree-sdk]]

请遵循 [unitree_sdk2_python 安装指南](https://github.com/unitreerobotics/unitree_sdk2_python#installation)。已使用 `unitree_sdk2py==1.0.1` 和 `cyclonedds==0.10.2` 进行测试：

```bash
conda create -y -n lerobot python=3.12
conda activate lerobot
git clone https://github.com/unitreerobotics/unitree_sdk2_python.git
cd unitree_sdk2_python
pip install -e .
cd ..
```

### 安装 LeRobot[[install-lerobot]]

```bash
conda install ffmpeg -c conda-forge
conda install -c conda-forge "pinocchio>=3.0.0,<4.0.0"
git clone https://github.com/huggingface/lerobot.git
cd lerobot
pip install -e '.[unitree_g1]'
```

<Tip>
  目前，必须从 conda-forge（而不是 pip）安装
  pinocchio，以包含机械臂逆运动学（IK）所需的 CasADi 绑定。
</Tip>

### 测试安装（仿真）[[test-the-installation-simulation]]

仿真环境有自己的一组依赖项。请查看仿真环境依赖项：[Unitree G1 Mujoco EnvHub](https://huggingface.co/lerobot/unitree-g1-mujoco/tree/main)。

```bash
pip install mujoco loguru msgpack msgpack-numpy
```

```bash
lerobot-teleoperate \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --teleop.type=unitree_g1 \
  --teleop.id=wbc_unitree \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "localhost", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30, "warmup_s": 5}}' \
  --display_data=true \
  --robot.controller=GrootLocomotionController
```

这将为 G1 启动一个 [MuJoCo 仿真实例](https://huggingface.co/lerobot/unitree-g1-mujoco/tree/main)。你可以在启动前将游戏手柄连接到你的机器，以便在仿真中控制机器人的运动。我们通过 `--robot.controller` 支持 [HolosomaLocomotionController](https://github.com/amazon-far/holosoma) 和 [GrootLocomotionController](https://github.com/NVlabs/GR00T-WholeBodyControl) 两者。

- 按 `9` 释放机器人
- 按 `7` / `8` 升高 / 降低腰部高度

#### 选择末端执行器[[choosing-the-end-effector]]

`--robot.end_effector` 指定手臂末端安装什么：`dex1` 表示平行夹爪（默认），`dex3` 表示三指手，`dummy` 表示裸露腕部。在仿真中，它会选择 MuJoCo 模型，而该模型决定手指执行器以及场景中携带哪些相机——腕部相机安装在末端执行器（end effector）上，因此 `dummy` 只有 `head_camera`。

```bash
lerobot-teleoperate \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --robot.end_effector=dex3 \
  --teleop.id=wbc_unitree \
  --robot.controller=GrootLocomotionController
```

仿真通过 ZMQ 在 `--robot.sim_camera_port`（默认为 5555）上发布模型相机，`--robot.cameras` 中的 `zmq` 相机正是从该端口读取。传入 `--robot.sim_publish_images=false` 可改为打开 MuJoCo 的交互式窗口：仿真要么渲染其相机，要么渲染其窗口，绝不会同时渲染两者，因为离屏上下文属于创建它们的线程，而不是查看器的线程。`--robot.sim_onscreen` 直接指定这一选择，而不是将其留给相机设置，同时要求两者会被拒绝；将它与 `--robot.sim_publish_images` 都设为 false 即可两者都不渲染，这正是无显示器的机器可以做的。

### 连接到实体机器人[[connect-to-the-physical-robot]]

G1 的以太网 IP 固定为 `192.168.123.164`。你的机器必须在同一子网上具有静态 IP：`192.168.123.x`，其中 `x ≠ 164`。

```bash
# 将 'enp131s0' 替换为你的以太网接口名称（使用 `ip a` 查看）
sudo ip addr flush dev enp131s0
sudo ip addr add 192.168.123.200/24 dev enp131s0
sudo ip link set enp131s0 up
```

### SSH 登录机器人[[ssh-into-the-robot]]

```bash
ssh unitree@192.168.123.164
# 密码：123
```

### 通过以太网共享互联网[[share-internet-via-ethernet]]

G1 需要互联网访问来克隆仓库并安装软件包。通过以太网共享你的笔记本电脑连接：

**在你的笔记本电脑上：**

```bash
sudo sysctl -w net.ipv4.ip_forward=1

# 将 wlp132s0f0 替换为你的 WiFi 接口名称
sudo iptables -t nat -A POSTROUTING -o wlp132s0f0 -s 192.168.123.0/24 -j MASQUERADE
sudo iptables -A FORWARD -i wlp132s0f0 -o enp131s0 -m state --state RELATED,ESTABLISHED -j ACCEPT
sudo iptables -A FORWARD -i enp131s0 -o wlp132s0f0 -j ACCEPT
```

**在 G1 上：**

```bash
sudo ip route del default 2>/dev/null || true
sudo ip route add default via 192.168.123.200 dev eth0
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf

# 验证
ping -c 3 8.8.8.8
```

### （可选）在机器人上启用 WiFi[[optional-enable-wifi-on-the-robot]]

如需无线 SSH 访问，你可以在 G1 上启用 WiFi（默认被阻止）：

```bash
sudo rfkill unblock all
sudo ip link set wlan0 up
sudo nmcli radio wifi on
sudo nmcli device set wlan0 managed yes
sudo systemctl restart NetworkManager
```

**连接到 WiFi 网络：**

```bash
nmcli device wifi list

sudo nmcli connection add type wifi ifname wlan0 con-name "YourNetwork" ssid "YourNetwork"
sudo nmcli connection modify "YourNetwork" wifi-sec.key-mgmt wpa-psk
sudo nmcli connection modify "YourNetwork" wifi-sec.psk "YourPassword"
sudo nmcli connection modify "YourNetwork" connection.autoconnect yes
sudo nmcli connection up "YourNetwork"

ip a show wlan0
```

然后你可以通过 WiFi 而不是以太网进行 SSH：

```bash
ssh unitree@<ROBOT_WIFI_IP>
# 密码：123
```

## 第 2 部分：遥操作与运动[[part-2-teleoperation-locomotion]]

### 运行机器人服务器[[run-the-robot-server]]

在机器人上（从 `~/lerobot` 目录）：

```bash
cd ~/lerobot
python src/lerobot/robots/unitree_g1/run_g1_server.py --camera
```

### 运行运动策略[[run-the-locomotion-policy]]

你可以通过以太网、WiFi（实验性）从笔记本电脑运行遥操作（teleoperation）客户端，也可以直接在机器人本身上运行。请注意网络可能引入的延迟。

**从你的笔记本电脑：**

```bash
lerobot-teleoperate \
  --robot.type=unitree_g1 \
  --robot.is_simulation=false \
  --robot.robot_ip=<ROBOT_IP> \
  --teleop.type=unitree_g1 \
  --teleop.id=wbc_unitree \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "<ROBOT_IP>", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30}}' \
  --display_data=true \
  --robot.controller=HolosomaLocomotionController
```

我们通过 `--robot.controller` 支持 [GrootLocomotionController](https://github.com/NVlabs/GR00T-WholeBodyControl) 和 [HolosomaLocomotionController](https://github.com/amazon-far/holosoma) 两者。

## 第 3 部分：使用 Homunculus 外骨骼进行移动操作[[part-3-loco-manipulation-with-the-homunculus-exoskeleton]]

我们通过 Homunculus 外骨骼提供了一种移动操作（loco-manipulation）解决方案——这是一个用于全身控制的开源 7 自由度（DoF）外骨骼。请在[此处](https://github.com/nepyope/hmc_exo)查看。

### 校准[[calibrate]]

```bash
lerobot-calibrate \
  --teleop.type=unitree_g1 \
  --teleop.left_arm_config.port=/dev/ttyACM1 \
  --teleop.right_arm_config.port=/dev/ttyACM0 \
  --teleop.id=exo
```

在校准期间，请让每个关节在其整个范围内运动。佩戴调整好后，将关节移动到中立位置并按 `n` 继续。

### 录制数据集[[record-a-dataset]]

```bash
lerobot-record \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "localhost", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30}}' \
  --teleop.type=unitree_g1 \
  --teleop.left_arm_config.port=/dev/ttyACM1 \
  --teleop.right_arm_config.port=/dev/ttyACM0 \
  --teleop.id=exo \
  --dataset.repo_id=your-username/dataset-name \
  --dataset.single_task="Test" \
  --dataset.num_episodes=2 \
  --dataset.episode_time_s=5 \
  --dataset.reset_time_s=5 \
  --dataset.push_to_hub=true \
  --dataset.streaming_encoding=true \
  --dataset.encoder_threads=2
```

> **注意：** 如果你只使用摇杆，请省略 `--teleop.left_arm_config.port` 和 `--teleop.right_arm_config.port`。

示例数据集：[nepyope/unitree_box_move_blue_full](https://huggingface.co/datasets/nepyope/unitree_box_move_blue_full)

## 第 4 部分：训练与推理[[part-4-training-inference]]

### 训练[[train]]

```bash
python src/lerobot/scripts/lerobot_train.py \
  --dataset.repo_id=your-username/dataset-name  \
  --policy.type=pi05 \
  --output_dir=./outputs/pi05_training \
  --job_name=pi05_training \
  --policy.repo_id=your-username/your-repo-id \
  --policy.pretrained_path=lerobot/pi05_base \
  --policy.compile_model=true \
  --policy.gradient_checkpointing=true \
  --wandb.enable=true \
  --policy.dtype=bfloat16 \
  --policy.freeze_vision_encoder=false \
  --policy.train_expert_only=false \
  --steps=3000 \
  --policy.device=cuda \
  --batch_size=32
```

### 使用 RTC 进行推理[[inference-with-rtc]]

训练完成后，我们建议使用推理时 RTC 部署策略（policy）：

```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=your-username/your-repo-id \
  --policy.device=cuda \
  --robot.type=unitree_g1 \
  --robot.is_simulation=false \
  --robot.controller=HolosomaLocomotionController \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "<ROBOT_IP>", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30}}' \
  --task="task_description" \
  --duration=1000 \
  --fps=30 \
  --inference.type=rtc
```

## 第 5 部分：SONIC 全身控制（潜在令牌策略）[[part-5-sonic-whole-body-control-latent-token-policies]]

LeRobot 现在将 NVIDIA [SONIC](https://github.com/NVIDIA/sonic) 全身部署栈的**解码器**部分移植为 `SonicWholeBodyController`。该策略（policy）不再命令关节，而是在每个控制周期输出一个 64 维**潜在运动令牌**（`motion_token.{i}.pos`）；SONIC 解码器将该令牌加上最近的本体感觉（proprioception）历史映射为一个残差动作，该动作经过缩放并加到站立姿态上，从而为全部 29 个自由度（DoF）生成 50 Hz 的关节位置目标。

控制器从 [`lerobot/sonic_decoder`](https://huggingface.co/lerobot/sonic_decoder) 加载其 ONNX 解码器以及所有部署常量（PD 增益、`default_angles`、`action_scale` 和中性令牌）。该仓库还附带一个蒸馏的低延迟解码器，可通过控制器的 `policy_type="low_latency"` 参数选择（默认为 `"default"`）。

### 在仿真中测试[[test-in-simulation]]

任何在 SONIC 运动令牌上训练的、输出令牌的策略（policy）（例如 [`nepyope/sonic_walk`](https://huggingface.co/nepyope/sonic_walk)）都可以驱动它：

```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=nepyope/sonic_walk \
  --policy.device=cuda \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --robot.controller=SonicWholeBodyController \
  --robot.cameras='{"ego_view": {"type": "zmq", "server_address": "localhost", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30, "warmup_s": 15}}'
```

### 在实体机器人上运行[[run-on-the-physical-robot]]

在硬件上，请使用[异步推理](./async)运行策略（policy），而不是使用单个 `lerobot-rollout` 循环。从笔记本电脑驱动的 rollout 会将网络置于控制回路中间：每一步都会阻塞等待推理，而一旦出现一次卡顿，就会让 50 Hz 的平衡回路停滞，而此时机器人正站在上面。异步推理将两者拆分——策略运行在你的 GPU 机器上，而机器人客户端运行在 G1 的 Jetson 上，因此 SONIC 控制器线程和 `rt/lowcmd` 保持在板载运行，网络中只传输 64 维令牌块。

三个进程，其中第 2 部分中的机器人服务器全程运行：

```text
GPU machine                     G1 (Jetson)
policy_server  ◄── gRPC ──►  robot_client: UnitreeG1 + SONIC decoder @ 50 Hz
  checkpoint                        │ ZMQ (lowcmd 6000, lowstate 6001, camera 5555)
                                    ▼
                             run_g1_server.py  ◄──► rt/lowcmd, rt/lowstate (DDS)
```

先在 GPU 机器上启动策略服务器：

```bash
python -m lerobot.async_inference.policy_server \
  --host=0.0.0.0 \
  --port=8080 \
  --fps=30
```

在机器人上，启动服务器（桥接 + 相机）：

```bash
python src/lerobot/robots/unitree_g1/run_g1_server.py --camera
```

然后，在机器人上的第二个终端中启动客户端。机器人侧的所有内容都使用回环地址，因为桥接运行在同一台机器上：

```bash
python -m lerobot.async_inference.robot_client \
  --server_address=<GPU_MACHINE_IP>:8080 \
  --policy_type=pi05 \
  --pretrained_name_or_path=nepyope/sonic_walk \
  --policy_device=cuda \
  --actions_per_chunk=50 \
  --fps=30 \
  --task="walk forward" \
  --robot.type=unitree_g1 \
  --robot.is_simulation=false \
  --robot.robot_ip=127.0.0.1 \
  --robot.controller=SonicWholeBodyController \
  --robot.cameras='{"ego_view": {"type": "zmq", "server_address": "127.0.0.1", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30, "warmup_s": 5}}'
```

需要注意几点：

- `--policy_device` 是 _服务器_ 将策略加载到的设备——客户端在握手期间会发送该参数。
- `--actions_per_chunk` 不得超过检查点的分块大小（对于 `nepyope/sonic_walk` 为 50）。
- 使用 `SonicWholeBodyController` 时，观测状态（observation state）是 64 维令牌回显，而不是 29 个关节位置，因此检查点必须针对同一状态进行训练。

连接时，机器人会先将每个关节缓和地移动到解码器的 `default_angles`，然后控制器才接管，因此首批策略命令不会从连接时的姿态突然跳变。
