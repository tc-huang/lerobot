# HIL-SERL 真实机器人训练工作流指南[[hil-serl-real-robot-training-workflow-guide]]

在本教程中，你将使用 LeRobot 完成完整的人在回路中的样本高效强化学习（Human-in-the-Loop Sample-Efficient Reinforcement Learning，HIL-SERL）工作流。你将掌握在真实机器人上仅用几个小时就能使用 RL 训练策略的方法。

HIL-SERL 是一种样本高效的强化学习算法，它将人类演示与在线学习和人类干预相结合。该方法从一小组人类演示开始，用它们训练奖励分类器，然后采用 actor-learner 架构，人类可以在策略（policy）执行期间进行干预，以引导探索并纠正不安全行为。在本教程中，你将使用游戏手柄在学习过程中提供干预并控制机器人。

它结合了三个关键要素：

1. **离线演示与奖励分类器：** 少量人类遥操作片段加上基于视觉的成功检测器，为策略（policy）提供经过塑形的起点。

2. **带人类干预的机器人上的 actor / learner 循环：** 分布式 Soft Actor Critic（SAC）learner 更新策略，而 actor 在物理机器人上探索；人类可以随时介入，以纠正危险或低效的行为。

3. **安全与效率工具：** 关节/末端执行器（EE）边界、裁剪感兴趣区域（ROI）预处理和 WandB 监控，使数据保持有用并确保硬件安全。

这些要素共同使 HIL-SERL 达到接近完美的任务成功率，并比仅模仿学习的基线实现更快的周期时间。

## 我需要什么？[[what-do-i-need]]

- 一个游戏手柄（推荐）或键盘，用于控制机器人
- 一块 Nvidia GPU
- 一台带有从臂和主臂的真实机器人（如果使用键盘或游戏手柄，则此项可选）
- 用于运动学（kinematics）包的机器人 URDF 文件（请查看 `lerobot/model/kinematics.py`）

## 我可以训练哪些类型的任务？[[what-kind-of-tasks-can-i-train]]

你可以使用 HIL-SERL 在各种操作任务上进行训练。以下是一些建议：

- 从简单任务开始，以理解系统如何工作。
  - 将方块推到目标区域
  - 用夹爪拾取并举起方块
- 避免极长视界（horizon）的任务。专注于可以在 5-10 秒内完成的任务。
- 一旦你很好地理解了系统如何工作，就可以尝试更复杂的任务和更长的视界。
  - 拾取并放置方块
  - 双臂任务，用两条手臂拾取物体
  - 交接任务，将物体从一条手臂转移到另一条手臂
  - 大胆尝试！

## 安装带 HIL-SERL 的 LeRobot[[install-lerobot-with-hil-serl]]

要安装带 HIL-SERL 的 LeRobot，你需要安装 `hilserl` 附加项。

```bash
pip install -e ".[hilserl]"
```

## 真实机器人训练工作流[[real-robot-training-workflow]]

### 理解配置[[understanding-configuration]]

训练过程从为 HIL-SERL 环境进行正确配置开始。主配置类是 `lerobot/rl/gym_manipulator.py` 中的 `GymManipulatorConfig`，其中包含嵌套的 `HILSerlRobotEnvConfig`（定义于 `lerobot/envs/configs.py`）和 `DatasetConfig`。该配置被组织为多个专注的嵌套子配置：

<!-- prettier-ignore-start -->
```python
class GymManipulatorConfig:
    env: HILSerlRobotEnvConfig    # 环境配置（嵌套）
    dataset: DatasetConfig    # 数据集记录/回放配置（嵌套）
    mode: str | None = None    # "record"、"replay" 或 None（用于训练）
    device: str = "cpu"    # 计算设备

class HILSerlRobotEnvConfig(EnvConfig):
    robot: RobotConfig | None = None    # 主机器人代理（定义于 `lerobot/robots`）
    teleop: TeleoperatorConfig | None = None    # 遥操作设备代理，例如游戏手柄或主臂
    processor: HILSerlProcessorConfig    # 处理流水线配置（嵌套）
    name: str = "real_robot"    # 环境名称
    task: str | None = None    # 任务标识符
    fps: int = 10    # 控制频率

# 嵌套处理器配置
class HILSerlProcessorConfig:
    control_mode: str = "gamepad"    # 控制模式
    observation: ObservationConfig | None = None    # 观测处理设置
    image_preprocessing: ImagePreprocessingConfig | None = None    # 图像裁剪/缩放设置
    gripper: GripperConfig | None = None    # 夹爪控制与惩罚设置
    reset: ResetConfig | None = None    # 环境重置与时序设置
    inverse_kinematics: InverseKinematicsConfig | None = None    # IK 处理设置
    reward_classifier: RewardClassifierConfig | None = None    # 奖励分类器设置
    max_gripper_pos: float | None = 100.0    # 最大夹爪位置

# 子配置类
class ObservationConfig:
    add_joint_velocity_to_observation: bool = False    # 将关节速度添加到状态
    add_current_to_observation: bool = False    # 将电机电流添加到状态
    add_ee_pose_to_observation: bool = False    # 将末端执行器位姿添加到状态
    display_cameras: bool = False    # 执行期间显示相机画面

class ImagePreprocessingConfig:
    crop_params_dict: dict[str, tuple[int, int, int, int]] | None = None    # 图像裁剪参数
    resize_size: tuple[int, int] | None = None    # 目标图像尺寸

class GripperConfig:
    use_gripper: bool = True    # 启用夹爪控制
    gripper_penalty: float = 0.0    # 不当夹爪使用惩罚

class ResetConfig:
    fixed_reset_joint_positions: list[float] | None = None    # 重置用关节位置
    reset_time_s: float = 5.0    # 重置期间等待时间
    control_time_s: float = 20.0    # 最大片段持续时间
    terminate_on_success: bool = True    # 是否在检测到成功时终止片段

class InverseKinematicsConfig:
    urdf_path: str | None = None    # 机器人 URDF 文件路径
    target_frame_name: str | None = None    # 末端执行器坐标系名称
    end_effector_bounds: dict[str, list[float]] | None = None    # EE 工作空间边界
    end_effector_step_sizes: dict[str, float] | None = None    # 各轴 EE 步长

class RewardClassifierConfig:
    pretrained_path: str | None = None    # 预训练奖励分类器路径
    success_threshold: float = 0.5    # 成功检测阈值
    success_reward: float = 1.0    # 成功片段的奖励值

# 数据集配置
class DatasetConfig:
    repo_id: str    # LeRobot 数据集仓库 ID
    task: str    # 任务标识符
    root: str | None = None    # 本地数据集根目录
    num_episodes_to_record: int = 5    # 要记录的片段数量
    replay_episode: int | None = None    # 用于回放的片段索引
    push_to_hub: bool = False    # 是否将数据集推送到 Hub
```
<!-- prettier-ignore-end -->

### 处理器流水线架构[[processor-pipeline-architecture]]

HIL-SERL 使用模块化的处理器流水线架构，通过一系列可组合步骤处理机器人观测和动作。该流水线分为两个主要组成部分：

#### 环境处理器流水线[[environment-processor-pipeline]]

环境处理器（`env_processor`）处理传入的观测（observation）和环境状态：

1. **VanillaObservationProcessorStep**：将原始机器人观测转换为标准化格式
2. **JointVelocityProcessorStep**（可选）：将关节速度信息添加到观测
3. **MotorCurrentProcessorStep**（可选）：将电机电流读数添加到观测
4. **ForwardKinematicsJointsToEE**（可选）：根据关节位置计算末端执行器位姿
5. **ImageCropResizeProcessorStep**（可选）：裁剪并缩放相机图像
6. **TimeLimitProcessorStep**（可选）：强制执行片段时间限制
7. **GripperPenaltyProcessorStep**（可选）：对不当夹爪使用施加惩罚
8. **RewardClassifierProcessorStep**（可选）：使用视觉模型进行自动奖励检测
9. **AddBatchDimensionProcessorStep**：将数据转换为批处理格式，以供神经网络处理
10. **DeviceProcessorStep**：将数据移动到指定的计算设备（CPU/GPU）

#### 动作处理器流水线[[action-processor-pipeline]]

动作处理器（`action_processor`）处理传出的动作和人类干预：

1. **AddTeleopActionAsComplimentaryDataStep**：捕获遥操作动作以进行记录
2. **AddTeleopEventsAsInfoStep**：记录干预事件和片段控制信号
3. **InterventionActionProcessorStep**：处理人类干预和片段终止
4. **Inverse Kinematics Pipeline**（启用时）：
   - **MapDeltaActionToRobotActionStep**：将增量动作转换为机器人动作格式
   - **EEReferenceAndDelta**：计算末端执行器参考位姿和增量运动
   - **EEBoundsAndSafety**：强制执行工作空间安全边界
   - **InverseKinematicsEEToJoints**：将末端执行器动作转换为关节目标
   - **GripperVelocityToJoint**：处理夹爪控制命令

#### 配置示例[[configuration-examples]]

**基本观测处理**：

```json
{
  "env": {
    "processor": {
      "observation": {
        "add_joint_velocity_to_observation": true,
        "add_current_to_observation": false,
        "display_cameras": false
      }
    }
  }
}
```

**图像处理**：

```json
{
  "env": {
    "processor": {
      "image_preprocessing": {
        "crop_params_dict": {
          "observation.images.front": [180, 250, 120, 150],
          "observation.images.side": [180, 207, 180, 200]
        },
        "resize_size": [128, 128]
      }
    }
  }
}
```

**逆运动学设置**：

```json
{
  "env": {
    "processor": {
      "inverse_kinematics": {
        "urdf_path": "path/to/robot.urdf",
        "target_frame_name": "end_effector",
        "end_effector_bounds": {
          "min": [0.16, -0.08, 0.03],
          "max": [0.24, 0.2, 0.1]
        },
        "end_effector_step_sizes": {
          "x": 0.02,
          "y": 0.02,
          "z": 0.02
        }
      }
    }
  }
}
```

### 高级观测处理[[advanced-observation-processing]]

HIL-SERL 框架支持额外的观测处理功能，这些功能可以改进策略（policy）学习：

#### 关节速度处理[[joint-velocity-processing]]

启用关节速度估计，以便为策略（policy）提供运动信息：

```json
{
  "env": {
    "processor": {
      "observation": {
        "add_joint_velocity_to_observation": true
      }
    }
  }
}
```

该处理器：

- 使用连续关节位置读数之间的有限差分估计关节速度
- 将速度信息添加到观测（observation）状态向量
- 适用于需要运动感知以完成动态任务的策略

#### 电机电流处理[[motor-current-processing]]

监控电机电流，以检测接触力和负载条件：

```json
{
  "env": {
    "processor": {
      "observation": {
        "add_current_to_observation": true
      }
    }
  }
}
```

该处理器：

- 从机器人控制系统中读取电机电流值
- 将电流测量值添加到观测状态向量
- 有助于检测接触事件、物体重量和机械阻力
- 适用于接触丰富的操作任务

#### 组合观测处理[[combined-observation-processing]]

你可以同时启用多个观测处理功能：

```json
{
  "env": {
    "processor": {
      "observation": {
        "add_joint_velocity_to_observation": true,
        "add_current_to_observation": true,
        "display_cameras": false
      }
    }
  }
}
```

**注意**：启用额外的观测功能会增加状态空间维度，这可能需要调整你的策略（policy）网络架构，并可能需要收集更多训练数据。

### 寻找机器人工作空间边界[[finding-robot-workspace-bounds]]

在收集演示之前，你需要确定机器人合适的操作边界。

这有助于从两方面简化在真实机器人上学习的问题：1）将机器人的操作空间限制到能够解决任务并避免不必要或不安全探索的特定区域；2）允许在末端执行器空间而不是关节空间中进行训练。根据经验，在操作任务中，在关节空间中进行强化学习通常更困难——有些任务在关节空间中几乎不可能学会，但当动作空间转换为末端执行器坐标后就可以学习。

**使用 lerobot-find-joint-limits**

该脚本可帮助你找到机器人末端执行器的安全操作边界。假设你有从臂和主臂，你可以使用该脚本找到从臂的边界，这些边界将在训练期间应用。
限制动作空间将减少智能体（agent）的冗余探索并保证安全性。

```bash
lerobot-find-joint-limits \
  --robot.type=so100_follower \
  --robot.port=/dev/tty.usbmodem58760431541 \
  --robot.id=black \
  --teleop.type=so100_leader \
  --teleop.port=/dev/tty.usbmodem58760431551 \
  --teleop.id=blue
```

**工作流**

1. 运行脚本，并让机器人遍历能够解决任务的空间
2. 脚本将记录末端执行器位置和关节角度的最小值和最大值，并将它们打印到控制台，例如：
   ```
   Max ee position [0.2417 0.2012 0.1027]
   Min ee position [0.1663 -0.0823 0.0336]
   Max joint positions [-20.0, -20.0, -20.0, -20.0, -20.0, -20.0]
   Min joint positions [50.0, 50.0, 50.0, 50.0, 50.0, 50.0]
   ```
3. 在环境配置中的 `env.processor.inverse_kinematics.end_effector_bounds` 下使用这些值（参见 `lerobot/envs/configs.py` 中的 `InverseKinematicsConfig`）

**示例配置**

```json
{
  "env": {
    "processor": {
      "inverse_kinematics": {
        "end_effector_bounds": {
          "max": [0.24, 0.2, 0.1],
          "min": [0.16, -0.08, 0.03]
        }
      }
    }
  }
}
```

### 收集演示[[collecting-demonstrations]]

在定义边界后，你可以安全地收集用于训练的演示。使用离策略（off-policy）算法训练 RL 允许我们使用收集的离线数据集，以提高学习过程的效率。

**设置记录模式**

为记录演示创建一个配置文件（或编辑现有文件，例如 [env_config.json](https://huggingface.co/datasets/lerobot/config_examples/resolve/main/rl/env_config.json)）：

1. 在根级别将 `mode` 设置为 `"record"`
2. 在 `dataset` 部分为数据集指定唯一的 `repo_id`（例如，"username/task_name"）
3. 将 `dataset` 部分中的 `num_episodes_to_record` 设置为你要收集的演示数量
4. 初始时将 `env.processor.image_preprocessing.crop_params_dict` 设置为 `{}`（我们稍后会确定裁剪参数）
5. 在 `env` 部分配置 `env.robot`、`env.teleop` 和其他硬件设置

示例配置部分：

```json
{
  "env": {
    "type": "gym_manipulator",
    "name": "real_robot",
    "fps": 10,
    "processor": {
      "control_mode": "gamepad",
      "observation": {
        "display_cameras": false
      },
      "image_preprocessing": {
        "crop_params_dict": {},
        "resize_size": [128, 128]
      },
      "gripper": {
        "use_gripper": true,
        "gripper_penalty": 0.0
      },
      "reset": {
        "reset_time_s": 5.0,
        "control_time_s": 20.0
      }
    },
    "robot": {
      // ... 机器人配置 ...
    },
    "teleop": {
      // ... 遥操作设备配置 ...
    }
  },
  "dataset": {
    "repo_id": "username/pick_lift_cube",
    "root": null,
    "task": "pick_and_lift",
    "num_episodes_to_record": 15,
    "replay_episode": 0,
    "push_to_hub": true
  },
  "mode": "record",
  "device": "cpu"
}
```

### 使用遥操作设备[[using-a-teleoperation-device]]

除了机器人之外，你还需要一个遥操作设备来控制它，以便收集任务数据集并在在线训练期间进行干预。
我们支持使用游戏手柄、键盘或机器人的主臂。

HIL-SERL 在机器人的末端执行器空间中学习动作。因此，遥操作将控制末端执行器的 x、y、z 位移。

末端执行器变换由处理器流水线（`InverseKinematicsRLStep`、`EEBoundsAndSafety`、`EEReferenceAndDelta`、`GripperVelocityToJoint`）应用，这些流水线配置在 `env.processor.inverse_kinematics`（`InverseKinematicsConfig`）以及 `env.processor.gripper` / `env.processor.max_gripper_pos` 下。与末端执行器空间相关的默认值如下：

<!-- prettier-ignore-start -->
```python
class InverseKinematicsConfig:
    """Configuration for inverse kinematics processing."""

    urdf_path: str | None = None
    target_frame_name: str | None = None
    # 末端执行器在 x、y、z 方向上的边界
    end_effector_bounds: dict[str, list[float]] | None = None
    # 末端执行器在 x、y、z 方向上的最大步长
    end_effector_step_sizes: dict[str, float] | None = None

class HILSerlProcessorConfig:
    ...
    # 夹爪打开时的最大夹爪位置
    max_gripper_pos: float | None = 100.0
```
<!-- prettier-ignore-end -->

`Teleoperator` 定义了遥操作设备。你可以在 `lerobot/teleoperators` 中查看可用遥操作设备的列表。

**设置游戏手柄**

游戏手柄提供了一种非常方便的方式来控制机器人和片段状态。

要设置游戏手柄，你需要将 `control_mode` 设置为 `"gamepad"`，并在配置文件中定义 `teleop` 部分。

```json
{
  "env": {
    "teleop": {
      "type": "gamepad",
      "use_gripper": true
    },
    "processor": {
      "control_mode": "gamepad",
      "gripper": {
        "use_gripper": true
      }
    }
  }
}
```

**设置 SO101 主臂**

SO101 主臂减少了齿轮，使其能够在探索期间移动并跟踪从臂。因此，接管比无齿轮的 SO100 更加平滑。

要设置 SO101 主臂，你需要将 `control_mode` 设置为 `"leader"`，并在配置文件中定义 `teleop` 部分。

```json
{
  "env": {
    "teleop": {
      "type": "so101_leader",
      "port": "/dev/tty.usbmodem585A0077921",
      "use_degrees": true
    },
    "processor": {
      "control_mode": "leader",
      "gripper": {
        "use_gripper": true
      }
    }
  }
}
```

为了标注片段的成功/失败，**你必须**使用键盘按 `s` 表示成功，按 `esc` 表示失败。
在在线训练期间，按 `space` 接管策略，再次按 `space` 将控制权交还给策略（policy）。

### 处理数据集[[processing-the-dataset]]

收集演示后，处理它们以确定最佳的相机裁剪区域。
强化学习对背景干扰很敏感，因此将图像裁剪到相关工作空间区域非常重要。

视觉 RL 算法直接从像素输入中学习，因此容易受到无关视觉信息的影响。背景元素，例如光照变化、阴影、人员移动或工作空间外的物体，可能会干扰学习过程。良好的 ROI 选择应该：

- 仅包含任务发生所需的基本工作空间
- 捕获机器人的末端执行器和任务中涉及的所有物体
- 排除不必要的背景元素和干扰物

注意：如果你已经知道裁剪参数，可以跳过此步骤，并仅在记录期间在配置文件中设置 `crop_params_dict`。

**确定裁剪参数**

使用 `crop_dataset_roi.py` 脚本以交互方式选择相机图像中的感兴趣区域：


1. 对于每个相机视图，脚本将显示第一帧（frame）

3. 按 'c' 确认选择
4. 对所有相机视图重复此操作
5. 脚本输出裁剪参数并创建一个新的裁剪数据集

**推荐的图像分辨率**

大多数基于视觉的策略（policy）已在 **128×128**（默认）或 **64×64** 像素的方形输入上验证过。因此，我们建议将 resize_size 参数设置为 [128, 128]——或者如果你需要节省 GPU 内存和带宽，则设置为 [64, 64]。其他分辨率也可行，但尚未经过广泛测试。

### 训练奖励分类器[[training-a-reward-classifier]]

奖励分类器（reward classifier）在 HIL-SERL 工作流中扮演重要角色，它自动化奖励分配并自动检测片段成功。奖励分类器不是手动定义奖励函数或依赖每个时间步的人类反馈，而是学习从视觉观测（observation）中预测成功/失败。这使 RL 算法能够通过基于机器人相机输入提供一致且自动的奖励信号来高效学习。

本指南解释如何为 LeRobot 的人在回路强化学习实现训练奖励分类器。奖励分类器学习在给定状态下预测奖励值，该值可用于 RL 设置中以训练策略（policy）。

**注意**：训练奖励分类器是可选的。你可以通过使用游戏手柄或键盘设备手动标注成功来开始第一轮 RL 实验。

`lerobot/rewards/classifier/modeling_classifier.py` 中的奖励分类器实现使用预训练视觉模型来处理图像。它可以输出单个值用于二元奖励，以预测成功/失败情况，也可以输出多个值用于多分类设置。

**为奖励分类器收集数据集**

在训练之前，你需要收集一个带有标注示例的数据集。在配置中设置 `mode: "record"` 并运行 `gym_manipulator.py` 即可开始收集观测、动作和奖励的数据集。

要收集数据集，你需要基于 HILSerlRobotEnvConfig 修改环境配置中的一些参数。

```bash
python -m lerobot.rl.gym_manipulator --config_path src/lerobot/configs/reward_classifier_train_config.json
```

**数据收集的关键参数**

- **mode**：将其设置为 `"record"` 以收集数据集（在根级别）
- **dataset.repo_id**：`"hf_username/dataset_name"`，数据集名称以及 Hub 上的仓库
- **dataset.num_episodes_to_record**：要记录的片段数量
- **env.processor.reset.terminate_on_success**：是否在检测到成功时自动终止片段（默认：`true`）
- **env.fps**：每秒记录的帧数
- **dataset.push_to_hub**：是否将数据集推送到 Hub

`env.processor.reset.terminate_on_success` 参数允许你控制片段终止行为。设置为 `false` 时，即使检测到成功，片段也会继续，从而允许你收集更多带有 reward=1 标签的正样本。这对于训练奖励分类器至关重要，因为它会在数据集中提供更多成功状态示例。设置为 `true`（默认）时，片段会在检测到成功时立即终止。

**重要**：对于奖励分类器训练，请设置 `terminate_on_success: false` 以收集足够的正样本。对于常规 HIL-SERL 训练，请保持为 `true`，以便在任务成功完成时自动终止片段。

### 使用 Actor-Learner 进行训练[[training-with-actor-learner]]

LeRobot 系统使用分布式 actor-learner（执行器-学习器）架构进行训练。该架构将机器人交互与学习过程解耦，使它们可以并发运行而不会相互阻塞。actor 服务器处理机器人观测和动作，将交互数据发送到 learner 服务器。learner 服务器执行梯度下降，并定期更新 actor 的策略（policy）权重。你需要启动两个进程：一个 learner 和一个 actor。

**配置设置**

创建训练配置文件（示例可在[此处](https://huggingface.co/datasets/lerobot/config_examples/resolve/main/rl/train_config.json)获取）。训练配置基于 `lerobot/rl/train_rl.py` 中的主 `TrainRLServerPipelineConfig` 类。

1. 配置策略（policy）设置（`type="gaussian_actor"`、`device` 等）
2. 在顶层 `algorithm` 块下配置算法设置（`type="sac"`、学习率、折扣等，定义于 `lerobot/rl/algorithms/sac/configuration_sac.py`）。
3. 将 `dataset` 设置为你的裁剪后数据集
4. 使用裁剪参数配置环境设置
5. 查看 [configuration_gaussian_actor.py](https://github.com/huggingface/lerobot/blob/main/src/lerobot/policies/gaussian_actor/configuration_gaussian_actor.py#L79) 中与 Gaussian Actor 相关的其他参数。
6. 验证 `policy` 配置是否正确，并具有适合你任务的 `input_features` 和 `output_features`。

**启动 Learner**

首先，启动 learner 服务器进程：

```bash
python -m lerobot.rl.learner --config_path src/lerobot/configs/train_config_hilserl_so100.json
```

learner 会：

- 初始化策略网络
- 准备回放缓冲区
- 打开一个 `gRPC` 服务器与 actor 通信
- 处理转移并更新策略

**启动 Actor**

在另一个终端中，使用相同配置启动 actor 进程：

```bash
python -m lerobot.rl.actor --config_path src/lerobot/configs/train_config_hilserl_so100.json
```

actor 会：

- 通过 `gRPC` 连接到 learner
- 初始化环境
- 执行策略的 rollout 以收集经验
- 将转移发送给 learner
- 接收更新后的策略参数

**训练流程**

训练会自动进行：

1. actor 在环境中执行策略
2. 收集转移并发送给 learner
3. learner 基于这些转移更新策略
4. 更新后的策略参数被发送回 actor
5. 该过程持续进行，直到达到指定的步数限制

**人在回路中**

- 高效学习的关键是让人类进行干预，以提供纠正性反馈并完成任务，从而帮助策略学习和探索。
- 要进行人类干预，你可以按下游戏手柄右上方的扳机按钮（或键盘上的 `space` 键）。这将暂停策略动作，并允许你接管。
- 一个成功的实验是：人类在开始时必须进行干预，但随着策略改进，干预次数逐渐减少。你可以在 `wandb` 仪表板中监控干预率。

### 人类干预指南[[guide-to-human-interventions]]

学习过程对干预策略非常敏感。需要运行几次才能理解如何有效干预。以下是一些提示和技巧：

- 在训练开始时，让策略探索几个片段。
- 避免长时间干预。尝试在机器人偏离轨道时进行干预，以纠正其行为。
- 一旦策略开始完成任务，即使并不完美，你也可以将干预限制为简单快速的动作，例如简单的抓取命令。

### 需要调整的关键超参数[[key-hyperparameters-to-tune]]

一些配置值对训练稳定性和速度有不成比例的影响：

- **`temperature_init`**（`algorithm.temperature_init`）——SAC 中的初始熵温度。较高的值会鼓励更多探索；较低的值会使策略在早期更加确定。一个良好的起点是 `1e-2`。我们观察到，将其设置得太高会使人类干预失效并减慢学习速度。
- **`policy_parameters_push_frequency`**（`policy.actor_learner_config.policy_parameters_push_frequency`）——从 learner 向 actor 推送权重的间隔，单位为*秒*。默认值为 `4 s`。减少到 **1-2 s** 可提供更新的权重（代价是更多网络流量）；仅在你的连接较慢时才增加，因为这会降低样本效率。
- **`storage_device`**（`policy.storage_device`）——learner 保存策略参数的设备。如果你有备用 GPU 内存，请将其设置为 `"cuda"`（而不是默认的 `"cpu"`）。将权重保留在 GPU 上可消除 CPU→GPU 传输开销，并可显著增加每秒 learner 更新次数。
