# 多任务 DiT 策略[[multitask-dit-policy]]

多任务扩散 Transformer（DiT）策略（Multitask DiT Policy）是原始扩散策略（Diffusion Policy）架构的演进，它利用带有文本与视觉条件化的大型 DiT 进行多任务机器人学习。该实现同时支持扩散（diffusion）与流匹配（flow matching）目标来进行动作生成，使机器人能够根据语言指令（language instructions）执行多样化的操作任务。

## 模型概览[[model-overview]]

该模型使用：

- **CLIP 视觉编码器**：处理来自多个相机视角的 RGB 图像
- **CLIP 文本编码器**：编码语言任务指令（冻结权重，并带有可学习投影）
- **扩散 Transformer**：在观测（observations）和语言条件下预测动作序列
- **两种目标**：同时支持扩散（DDPM/DDIM）与流匹配进行动作生成

这个模型令人兴奋，因为它仅用约 450M 参数和显著更少的训练，就能实现极高的灵巧性，足以与数十亿参数的
VLA 模型相竞争。

## 安装要求[[installation-requirements]]

多任务 DiT 策略有额外的依赖项。使用以下命令安装：

```bash
pip install lerobot[multi_task_dit]
```

这将安装所有必要的依赖项，包括用于 CLIP 模型的 HuggingFace Transformers 库。

## 用法[[usage]]

要在 LeRobot 配置中使用多任务 DiT，请将策略类型指定为：

```python
policy.type=multi_task_dit
```

## 训练[[training]]

### 基础训练命令[[basic-training-command]]

以下是在你的数据集上训练多任务 DiT 的完整训练命令：

```bash
lerobot-train \
  --dataset.repo_id=YOUR_DATASET \
  --output_dir=./outputs/multitask_dit_training \
  --batch_size=32 \
  --steps=5000 \
  --save_freq=500 \
  --log_freq=100 \
  --policy.type=multi_task_dit \
  --policy.device=cuda \
  --policy.repo_id="HF_USER/multitask-dit-your-robot" \
  --wandb.enable=true
```

### 推荐超参数与数据集细节（30Hz 控制频率）[[recommended-hyperparameters-and-dataset-details-30hz-control-frequency]]

为了获得可靠性能，请从以下建议的默认超参数开始：

```bash
lerobot-train \
  --dataset.repo_id=YOUR_DATASET \
  --output_dir=./outputs/mutitask_dit_training \
  --batch_size=320 \
  --steps=30000 \
  --policy.type=multi_task_dit \
  --policy.device=cuda \
  --policy.horizon=32 \
  --policy.n_action_steps=24 \
  --policy.objective=diffusion \
  --policy.noise_scheduler_type=DDPM \
  --policy.num_train_timesteps=100 \
  --policy.repo_id="HF_USER/multitask-dit-your-robot" \
  --wandb.enable=true
```

**关键参数：**

- **批量大小**：192-320 - 如果你可以使用支持该批量大小的 GPU，你将获得最佳训练动态
- **Horizon（预测时域）**：32 - 要预测的动作步数，在 30Hz 下约 1.0 秒
- **n_action_steps**：24 - 在 30Hz 下约 0.8 秒
- **目标**：`diffusion` - 从扩散开始，如果生成质量不佳，再尝试流匹配
- **训练步数**：对于单个任务，建议超过 30k 步

### 训练配置参数[[training-configuration-parameters]]

#### 目标选择[[objective-selection]]

在扩散与流匹配之间选择：

```bash
# 扩散目标（默认）
--policy.objective=diffusion \
--policy.noise_scheduler_type=DDPM \  # 或 "DDIM"
--policy.num_train_timesteps=100 \
--policy.num_inference_steps=10 \  # 用于更快的推理
--policy.beta_schedule=squaredcos_cap_v2 \  # 噪声调度类型
--policy.prediction_type=epsilon \  # "epsilon"（预测噪声）或 "sample"（预测干净样本）
--policy.clip_sample=true \  # 在去噪期间裁剪样本
--policy.clip_sample_range=1.0  # 裁剪范围 [-x, x]

# 流匹配目标
--policy.objective=flow_matching \
--policy.timestep_sampling_strategy=beta \  # 或 "uniform" | 实践中 beta 采样策略的性能似乎好得多
--policy.num_integration_steps=100 \
--policy.integration_method=euler \  # 或 "rk4"
--policy.sigma_min=0.0  # 流插值路径中的最小噪声
```

#### Transformer 架构[[transformer-architecture]]

根据数据集大小调整模型容量：

```bash
# 小型数据集（少于 100 个样本）
--policy.num_layers=4 \
--policy.hidden_dim=512 \
--policy.num_heads=8  # 理想情况下应为 hidden_dim // 64

# 中型数据集（100-5k 个样本）- 默认
--policy.num_layers=6 \
--policy.hidden_dim=512 \
--policy.num_heads=8  # 理想情况下应为 hidden_dim // 64

# 大型数据集（超过 5k 个样本）
--policy.num_layers=8 \
--policy.hidden_dim=512 \
--policy.num_heads=8   # 理想情况下应为 hidden_dim // 64
```

**位置编码选项：**

该模型支持两种用于动作序列的位置编码方法：

```bash
# 旋转位置编码（RoPE）- 默认，推荐
--policy.use_rope=true \
--policy.rope_base=10000.0  # RoPE 的基础频率

# 绝对位置编码
--policy.use_positional_encoding=true  # 为 true 时禁用 RoPE
```

**其他 Transformer 参数：**

```bash
--policy.dropout=0.1  # DiT 块的 dropout 率（0.0-1.0）
--policy.timestep_embed_dim=256  # 时间步嵌入维度
```

#### 视觉编码器配置[[vision-encoder-configuration]]

```bash
# 使用不同的 CLIP 模型以获得更强的表达能力，但会增加推理时间
# 根据任务复杂度和数据集大小尝试更大或更小的模型
--policy.vision_encoder_name=openai/clip-vit-large-patch14

# 为每个相机使用单独的视觉编码器
# 当相机特性差异显著时，这可能有用，但
# 请注意显存占用会增加。
--policy.use_separate_rgb_encoder_per_camera=true

# 图像预处理
--policy.image_resize_shape=[XXX,YYY] \ # 为了加速推理，你可能需要调整图像大小
--policy.image_crop_shape=[224,224] \
--policy.image_crop_is_random=true  # 训练时随机，推理时居中
```

#### 文本编码器配置[[text-encoder-configuration]]

```bash
# 使用不同的 CLIP 文本编码器模型
# 与视觉部分相同：根据以下因素尝试更大或更小的模型：
# 任务复杂度和数据集大小
--policy.text_encoder_name=openai/clip-vit-large-patch14
```

#### 学习率配置[[learning-rate-configuration]]

视觉编码器使用单独的学习率乘数，建议将 1/10 作为理想起点：

```bash
--policy.optimizer_lr=2e-5 \
--policy.vision_encoder_lr_multiplier=0.1  # 视觉编码器学习率 = 0.1 * optimizer_lr
```

### 训练调优指南[[training-tuning-guidelines]]

#### 1. 使用 Beta 采样的流匹配[[1-flow-matching-with-beta-sampling]]

这里的原始扩散实现基于 [TRI 的 LBM 论文](https://arxiv.org/abs/2507.05331) 中描述的工作

此外，我们实现了流匹配目标，[Boston Dynamics 博客文章](https://bostondynamics.com/blog/large-behavior-models-atlas-find-new-footing/) 对此进行了高层概述。

考虑测试流匹配目标，并评估你的任务中的性能差异：

```bash
--policy.objective=flow_matching \
--policy.timestep_sampling_strategy=beta \
--policy.timestep_sampling_alpha=1.5 \
--policy.timestep_sampling_beta=1.0 \
--policy.timestep_sampling_s=0.999
```

这尚未被证明对每个用户场景都是灵丹妙药，但它偶尔会带来更平滑、更一致的动作。

#### 2. Transformer 层数[[2-number-of-transformer-layers]]

使模型容量与数据集大小匹配：

- **小型数据集**（少于 100 个样本）：减少到 4 层
- **大型数据集**（超过 5k 个样本）：增加到 8 层

#### 3. `horizon` 调优[[3-horizon-tuning]]

模型可能对你选择的预测时域（horizon）很敏感。请根据控制频率，从约 1 秒的预测时域开始：

- **30 Hz 频率**：`horizon=30`
- **10 Hz 频率**：`horizon=10`

然后在此基础上尝试逐渐增大。预测时域决定模型预测未来多远之后的动作。

#### 4. `n_action_steps` 敏感性[[4-nactionsteps-sensitivity]]

模型也可能对 `n_action_steps` 非常敏感。请根据控制频率，从约 0.8 秒开始，并在此基础上调优：

- **较低的值**：反应更灵敏，但对于长时域任务可能不太稳定
- **较高的值**：更适合长时域执行，但开环失败的恢复能力有限

### 推理调优[[inference-tuning]]

为了加快推理，请使用采样步数更少的 DDIM：

```bash
--policy.noise_scheduler_type=DDIM \
--policy.num_inference_steps=10
```

### 恢复训练[[resuming-training]]

从检查点恢复训练：

```bash
lerobot-train \
  --config_path=./outputs/mutitask_dit_training/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

检查点目录应包含 `model.safetensors` 和 `config.json` 文件（训练期间会自动保存）。恢复时，配置会从检查点加载，因此你无需指定其他参数。

## 常见故障模式与调试[[common-failure-modes-and-debugging]]

训练这些模型可能很棘手。以下是常见的故障模式与调试方法：

### 空转 / 无运动[[idling-no-motion]]

模型可能在推理期间“崩溃”，导致静止或无运动。这种情况可能发生在：

1. **训练数据不足**：如果你只有 20-50 个样本，请尝试将数据集大小大致加倍。一旦超过 300 个样本，如果仍然出现这种情况，任务可能过于复杂。

2. **多个相似任务**：当你的数据集包含多个相似任务（例如，拿起 2 个不同的物体）时，模型可能过度依赖语言条件化，而语言条件化可能不够丰富。

**调试提示：**

- 增大数据集大小（加倍，直到超过 300 个样本）
- 训练更长时间，最多到 100k 步，即使损失（loss）趋于平稳
- 检查模型是否接收到正确的语言指令，或增加指令的多样性

### 执行错误任务[[executing-the-wrong-task]]

有时机器人会完全忽略你的指令并执行其他任务。这通常只会在你训练了多个任务时发生。

**可能原因：**

- 语言指令歧义
- 任务特定训练数据不足
- 模型在多任务数据集中混淆相似任务

**调试提示：**

- 验证语言指令的明确性，尤其是当多个任务之间的描述相似时
- 检查训练数据集中的任务分布，并为失败/被忽略的任务添加权重
- 考虑进行任务特定的微调

### 训练不稳定[[training-instability]]

如果训练损失不稳定或发散：

- 尝试将学习率调整到 `1e-5` 与 `3e-4` 之间
- 如果可能，增大批量大小
- 检查数据集归一化是否正确
- 验证图像预处理是否正常工作

## 性能注意事项[[performance-considerations]]

### GPU 要求[[gpu-requirements]]

- **推理**：建议至少使用 RTX 5070 Ti（或同等 GPU）以获得合理的速度性能
- **训练**：理想情况下，使用具有足够 VRAM 来加载大于 64 的批量大小的 GPU，这会根据图像观测（image observations）数量等因素而变化

### 批量大小建议[[batch-size-recommendations]]

- **最小值**：64（低于此值可能导致训练不稳定）
- **推荐值**：256-320（最佳性能，需要更大的 GPU）
