# 处理器简介[[introduction-to-processors]]

在机器人领域，机器人及其人类产生的数据与机器学习模型所期望的数据之间存在根本性不匹配。
机器人会输出原始传感器数据，例如摄像头图像和关节位置，这些数据在模型处理前需要进行归一化、批处理和设备放置。
来自人类的语言指令必须被分词为数值表示，而不同机器人使用不同的坐标系，需要进行标准化。

这一挑战同样延伸到模型输出。
模型可能输出末端执行器（end effector）位置，而机器人需要关节空间命令；或者遥操作器（teleoperator）产生相对运动，而机器人期望绝对命令。
模型预测通常是归一化的，需要转换回真实世界尺度。

跨域转换又增加了一层复杂性。
来自一种机器人设置的训练数据需要适配，以便部署到不同硬件上；使用特定摄像头配置训练的模型必须能适应新的布局；具有不同命名约定的数据集需要统一。

**处理器（processor）正是为此而生。** 它们充当通用翻译器，弥合这些差距，确保数据从传感器到模型再到执行器的无缝流动。
处理器处理将原始环境数据转换为模型可用输入以及反向转换所需的所有预处理和后处理步骤。

这意味着你可以像这样使用你最爱的策略（policy）：

```python
import torch

from lerobot.datasets import LeRobotDataset
from lerobot.policies import make_pre_post_processors
from lerobot.policies.your_policy import YourPolicy
from lerobot.processor import RobotProcessorPipeline, PolicyProcessorPipeline
dataset = LeRobotDataset("hf_user/dataset", episodes=[0])
sample = dataset[10]

model = YourPolicy.from_pretrained(
    "hf_user/model",
)
model.eval()
model.to("cuda")
preprocessor, postprocessor = make_pre_post_processors(model.config, pretrained_path="hf_user/model", dataset_stats=dataset.meta.stats)

preprocessed_sample = preprocessor(sample)
action = model.select_action(preprocessed_sample)
postprocessed_action = postprocessor(action)
```

## 什么是处理器？[[what-are-processors]]

在机器人领域，数据有多种形式：来自摄像头的图像、来自传感器的关节位置、来自用户的文本指令等。每种数据在模型能够有效使用之前都需要特定的转换。模型需要这些数据：

- **归一化（Normalized）**：缩放到适合神经网络处理的取值范围
- **批量化（Batched）**：按适当维度组织，以便进行批处理
- **分词化（Tokenized）**：将文本转换为数值表示
- **设备放置（Device-placed）**：移动到正确的硬件（CPU/GPU）
- **类型转换（Type-converted）**：转换为适当的数据类型

处理器通过可组合、可复用的步骤处理这些转换，这些步骤可以串联成管道。你可以把它们想象成一条模块化装配线，每个工位都会对你的数据执行特定转换。

## 核心概念[[core-concepts]]

### EnvTransition：通用数据容器[[envtransition-the-universal-data-container]]

`EnvTransition` 是在所有处理器中流动的基础数据结构。
它是一个类型化字典，表示一次完整的机器人-环境交互：

- **OBSERVATION**：所有传感器数据（图像、状态、本体感觉）
- **ACTION**：要执行或已执行的动作
- **REWARD**：强化学习信号
- **DONE/TRUNCATED**：片段边界指示符
- **INFO**：任意元数据
- **COMPLEMENTARY_DATA**：任务描述、索引、填充标志、步骤间数据

批处理转换器会将 `index`、`episode_index` 和 `frame_index` 等索引元数据保留在 `COMPLEMENTARY_DATA` 中。
在 `batch_to_transition` / `transition_to_batch` 往返过程中，`frame_index` 会保留其原始标量或张量值。
如果输入省略了 `frame_index`，转换器不会添加它。

### ProcessorStep：构建块[[processorstep-the-building-block]]

`ProcessorStep` 是处理转换的单个转换单元。它是一个抽象基类，有两个必需方法：

```python
from lerobot.processor import ProcessorStep, EnvTransition

class MyProcessorStep(ProcessorStep):
    """示例处理器步骤——继承并实现抽象方法。"""

    def __call__(self, transition: EnvTransition) -> EnvTransition:
        """转换 transition——必需的抽象方法。"""
        # 在此处编写处理逻辑
        return transition

    def transform_features(self, features):
        """声明该步骤如何转换特征形状/类型——必需的抽象方法。"""
        return features  # 大多数处理器会原样返回 features
```

`__call__` 是你的处理器步骤的核心。它接收一个 `EnvTransition` 并返回修改后的 `EnvTransition`。

`transform_features` 用于声明该步骤如何转换特征形状/类型。

### DataProcessorPipeline：通用编排器[[dataprocessorpipeline-the-generic-orchestrator]]

`DataProcessorPipeline[TInput, TOutput]` 将多个 `ProcessorStep` 实例串联在一起：

```python
from lerobot.processor import RobotProcessorPipeline, PolicyProcessorPipeline

# 用于机器人硬件（非批量数据）
robot_processor = RobotProcessorPipeline[RobotAction, RobotAction](
    steps=[step1, step2, step3],
    name="robot_pipeline"
)

# 用于模型训练/推理（批量数据）
policy_processor = PolicyProcessorPipeline[dict[str, Any], dict[str, Any]](
    steps=[step1, step2, step3],
    name="policy_pipeline"
)
```

## RobotProcessorPipeline 与 PolicyProcessorPipeline[[robotprocessorpipeline-vs-policyprocessorpipeline]]

关键区别在于它们处理的数据结构：

| 方面         | RobotProcessorPipeline            | PolicyProcessorPipeline                  |
| ------------ | --------------------------------- | ---------------------------------------- |
| **输入**     | `dict[str, Any]` - 单个机器人值   | `dict[str, Any]` - 批量张量              |
| **输出**     | `dict[str, Any]` - 单个机器人命令 | `torch.Tensor` - 策略预测                |
| **用例**     | 实时机器人控制                    | 模型训练/推理                            |
| **数据格式** | 非批量、异构                      | 批量、同构                               |
| **示例**     | `{"joint_1": 0.5}`                | `{"observation.state": tensor([[0.5]])}` |

**使用 `RobotProcessorPipeline`** 处理机器人硬件接口：

```python
# 机器人数据结构：用于观测和动作的 dict[str, Any]
robot_obs: dict[str, Any] = {
    "joint_1": 0.5,           # 单个关节值
    "joint_2": -0.3,
    "camera_0": image_array   # 原始摄像头数据
}

robot_action: dict[str, Any] = {
    "joint_1": 0.2,          # 目标关节位置
    "joint_2": 0.1,
    "gripper": 0.8
}
```

**使用 `PolicyProcessorPipeline`** 进行模型训练和批处理：

```python
# 策略数据结构：批量字典和张量
policy_batch: dict[str, Any] = {
    "observation.state": torch.tensor([[0.5, -0.3]]),      # 批量状态
    "observation.images.camera0": torch.tensor(...),        # 批量图像
    "action": torch.tensor([[0.2, 0.1, 0.8]])              # 批量动作
}

policy_action: torch.Tensor = torch.tensor([[0.2, 0.1, 0.8]])  # 模型输出张量
```

## 转换器函数[[converter-functions]]

LeRobot 在 `lerobot.processor.converters` 中提供转换器函数，以桥接不同的数据格式。这些函数处理机器人硬件数据结构、策略模型格式以及在处理器管道中流动的内部 `EnvTransition` 表示之间的关键转换。

| 类别                 | 函数                          | 描述                       |
| -------------------- | ----------------------------- | -------------------------- |
| **机器人硬件转换器** | `robot_action_to_transition`  | 机器人字典 → EnvTransition |
|                      | `observation_to_transition`   | 机器人观测 → EnvTransition |
|                      | `transition_to_robot_action`  | EnvTransition → 机器人字典 |
| **策略/训练转换器**  | `batch_to_transition`         | 批量字典 → EnvTransition   |
|                      | `transition_to_batch`         | EnvTransition → 批量字典   |
|                      | `policy_action_to_transition` | 策略张量 → EnvTransition   |
|                      | `transition_to_policy_action` | EnvTransition → 策略张量   |
| **实用工具**         | `create_transition`           | 使用默认值构建转换         |
|                      | `identity_transition`         | 直通转换器                 |

关键洞见是：**机器人硬件转换器**处理单个值和字典，而**策略/训练转换器**处理批量张量和模型输出。转换器函数会自动处理结构差异，因此你的处理器步骤可以专注于核心转换，而不必担心数据格式兼容性。

## 处理器示例[[processor-examples]]

以下示例展示了用于策略训练和推理的真实世界处理器配置。

以下是一个用于策略训练和推理的处理器示例：

```python
# 训练数据预处理（针对 GPU 性能优化顺序）
training_preprocessor = PolicyProcessorPipeline[dict[str, Any], dict[str, Any]](
    steps=[
        RenameObservationsProcessorStep(rename_map={}),     # 标准化键名
        AddBatchDimensionProcessorStep(),                   # 添加批量维度
        TokenizerProcessorStep(tokenizer_name="...", ...),  # 对语言进行分词
        DeviceProcessorStep(device="cuda"),                 # 先移动到 GPU
        NormalizerProcessorStep(features=..., stats=...),   # 在 GPU 上归一化
    ]
)

# 模型输出后处理
training_postprocessor = PolicyProcessorPipeline[torch.Tensor, torch.Tensor](
    steps=[
        DeviceProcessorStep(device="cpu"),                  # 移动到 CPU
        UnnormalizerProcessorStep(features=..., stats=...), # 反归一化
    ]
    to_transition=policy_action_to_transition,
    to_output=transition_to_policy_action,
)
```

### 机器人与策略（policy）使用处理器的交互[[an-interaction-between-a-robot-and-a-policy-with-processors]]

最常见的真实世界场景会结合两种管道类型：机器人硬件生成需要策略处理的观测，而策略输出需要与机器人兼容的后处理：

```python
# 实际部署：机器人传感器 → 模型 → 机器人命令
with torch.no_grad():
    while not done:
        raw_obs = robot.get_observation()  # dict[str, Any]

        # 将机器人观测添加到策略观测处理器

        policy_input = policy_preprocessor(raw_obs)  # 批量字典

        policy_output = policy.select_action(policy_input)  # 策略张量

        policy_action = policy_postprocessor(policy_output)

        # 将机器人动作添加到策略动作处理器

        robot.send_action(policy_action)
```

## 特征契约：形状与类型转换[[feature-contracts-shape-and-type-transformation]]

处理器不仅转换数据——它们还可以**改变数据结构本身**。`transform_features()` 方法会声明这些变化，这对于数据集记录和策略创建至关重要。

### 为什么特征契约很重要[[why-feature-contracts-matter]]

在构建数据集或策略时，LeRobot 需要知道：

- 处理后**将存在哪些数据字段**
- 每个字段**将具有什么形状和类型**
- 针对预期数据结构**如何配置模型**

```python
# 示例：一个向观测中添加速度的处理器
class VelocityProcessor(ObservationProcessorStep):
    def observation(self, obs):
        new_obs = obs.copy()
        if "observation.state" in obs:
            # 将计算出的速度字段拼接到状态中
            new_obs["observation.state"] = self._compute_velocity(obs["observation.state"])
        return new_obs

    def transform_features(self, features):
        """声明我们要添加的新速度字段。"""
        state_feature = features[PipelineFeatureType.OBSERVATION].get("observation.state")
        if state_feature:
            double_shape = (state_feature.shape[0] * 2,) if state_feature.shape else (2,)
            features[PipelineFeatureType.OBSERVATION]["observation.state"] = PolicyFeature(
                type=FeatureType.STATE, shape=double_shape
            )
        return features
```

### 特征规范函数[[feature-specification-functions]]

`create_initial_features()` 和 `aggregate_pipeline_dataset_features()` 解决了数据集创建中的一个关键问题：在任何数据处理之前确定最终的数据结构。
由于处理器管道可以添加新特征（如速度字段）、改变张量形状（如图像裁剪）或重命名键，数据集需要预先知道完整的输出规范，以便分配合适的存储并定义模式（schema）。
这些函数协同工作：先以机器人硬件规范（`create_initial_features()`）为起点，然后模拟整个管道转换（`aggregate_pipeline_dataset_features()`），计算出传递给 `LeRobotDataset.create()` 的最终特征字典，从而确保处理器输出与数据集期望存储的内容完全一致。

```python
from lerobot.datasets import aggregate_pipeline_dataset_features

# 从机器人的原始特征开始
initial_features = create_initial_features(
    observation=robot.observation_features,  # {"joint_1.pos": float, "camera_0": (480,640,3)}
    action=robot.action_features            # {"joint_1.pos": float, "gripper.pos": float}
)

# 应用处理器管道以计算最终特征
final_features = aggregate_pipeline_dataset_features(
    pipeline=my_processor_pipeline,
    initial_features=initial_features,
    use_videos=True
)

# 用于数据集创建
dataset = LeRobotDataset.create(
    repo_id="my_dataset",
    features=final_features,  # 确切知道应期望哪些数据
    ...
)
```

## 常见处理器步骤[[common-processor-steps]]

LeRobot 提供了许多已注册的处理器步骤。以下是最常用的核心处理器：

### 必备处理器[[essential-processors]]

- **`normalizer_processor`**：使用数据集统计信息（均值/标准差或最小值/最大值）归一化观测（observation）/动作（action）
- **`device_processor`**：将张量移动到 CPU/GPU，并可选择转换 dtype
- **`to_batch_processor`**：为转换添加批量维度，以兼容模型
- **`rename_observations_processor`**：使用映射字典重命名观测键
- **`tokenizer_processor`**：将自然语言任务描述分词为 token 和注意力掩码

## 总结[[summary]]

处理器通过提供以下内容，解决了机器人领域的数据转换问题：

- **模块化转换**：可组合、可复用的处理步骤
- **类型安全**：具备编译期检查的泛型管道
- **性能优化**：GPU 加速操作
- **机器人/策略区分**：为不同数据结构提供独立管道
- **全面的生态系统**：针对常见任务提供 30 多个已注册处理器

关键洞见：`RobotProcessorPipeline` 处理非批量的机器人硬件数据，而 `PolicyProcessorPipeline` 处理批量模型数据。为你的数据结构选择正确的工具！
