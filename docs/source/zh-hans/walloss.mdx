# WALL-OSS[[wall-oss]]

WALL-OSS 是由 [XSquare Robot](https://x2robot.com/en/research/68bc2cde8497d7f238dde690) 团队于 2025 年提出的、面向具身智能的开源基础模型。LeRobot 实现改编自其开源 [WallX](https://github.com/X-Square-Robot/wall-x) 仓库。

X Square Robot 的 WALL-OSS 现已集成到 Hugging Face 的 LeRobot 生态系统中。这是 LeRobot 与 X Square Robot 团队之间一个令人兴奋的合作项目。你现在可以通过 LeRobot 直接对 WALL-OSS 进行后训练、评估和部署。借此，我们希望让开源机器人社区更容易定制和部署 WALL-OSS 基础模型。阅读并探索 WALL-OSS 的 [论文](https://arxiv.org/pdf/2509.11766) 和 [代码](https://github.com/X-Square-Robot/wall-x)。

## 模型概述[[model-overview]]

WALL-OSS 团队正在构建具身基础模型，以捕获并压缩世界上最有价值的数据：连续、高保真的物理交互流。通过在该模型的决策与身体的真实体验之间建立直接反馈回路，一种真正可泛化的智能得以涌现——它不仅理解世界如何运作，还知道如何在其间有效行动。

  alt="WALL-OSS 概览"
  width="85%"

在技术层面，WALL-OSS 引入了一种紧密耦合的多模态架构（紧密耦合的 MoE 结构），整合了离散与连续动作建模策略。通过两阶段训练流程（Inspiration → Integration），该模型逐步统一语义推理与高频动作生成。其核心创新包括：

- **具身感知增强的多模态预训练**：在大规模统一的视觉-语言-动作数据上进行训练，以增强空间、因果和操作理解。
- **统一跨层级思维链（Uni-CoT）**：一个可微框架，统一了高层指令推理、子任务分解和细粒度动作合成，形成从“理解”到“执行”的连续链条。
- **专家混合（MoE）动作头**：根据任务阶段动态激活专家，并在离散或连续空间中建模动作，以保持稳定的 VLM 先验。
- **两阶段训练范式**：
  - **Inspiration 阶段**：注入离散动作先验，以增强空间理解和语义-动作对齐。
  - **Integration 阶段**：使用流匹配实现高频连续控制。

   ```bash
   pip install -e ".[wallx]"
   ```

## 使用方法[[usage]]

要在 LeRobot 中使用 WallX，请将策略类型指定为：

```python
policy.type=wall_x
```

### 文本生成与交互式控制[[text-generation-and-interactive-control]]

WALL-OSS 通过来自
[自带策略](./bring_your_own_policies#adding-a-text-head-the-language-contract) 的策略契约暴露原生文本生成能力。
运行时会在执行 WALL-OSS 的正常输入流程之前提供 `query_kind` 和调用方拥有的 `text`：

```python
request = {
    **observation,
    "query_kind": "vqa",
    "text": "Which object is closest to the right gripper?",
}
processed_batch = preprocessor(request)
answer = policy.generate_text(processed_batch)
```

`vqa` 会将问题保留为用户载荷。`next_subtask` 会在 `${subtask}` 之前应用检查点配方（recipe）。WALL-X 直接为其 Qwen 视觉语言专家覆盖公共 `generate_text(processed_batch)` API，并通过 `supports_text_generation()` 报告该能力。

交互式语言运行时可以生成一个子任务，然后让 WALL-OSS 的动作预测以其为条件：

```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=your-org/your-wall-oss-checkpoint \
  --robot.type=your_robot_type \
  --robot.port=/dev/your_robot_port \
  --task="clear the table" \
  --interactive=true
```

在 `/start` 之后，使用 `/vqa <question>` 进行基于图像的 VQA，或使用
`/autosteer <goal>` 进行由配方支持的下一子任务生成。`/subtask <text>`
会绕过生成，并将指令直接发送到动作推理。

## 训练[[training]]

要训练 WallX，你可以使用标准 LeRobot 训练脚本，并采用合适的配置：

```bash
lerobot-train \
    --dataset.repo_id=your_dataset \
    --policy.type=wall_x \
    --output_dir=./outputs/wallx_training \
    --job_name=wallx_training \
    --policy.repo_id=your_repo_id \
    --policy.pretrained_name_or_path=x-square-robot/wall-oss-flow \
    --policy.prediction_mode=diffusion \
    --policy.attn_implementation=eager \
    --steps=3000 \
    --policy.device=cuda \
    --batch_size=32
```

### 使用语言标注进行训练[[train-with-language-annotations]]

WALL-X 使用其内置配方，从 LeRobot 的可选语言列进行训练。仅在要替换该配方时才设置 `recipe_path`：

```bash
lerobot-train \
  --dataset.repo_id=your_org/your_language_annotated_dataset \
  --policy.type=wall_x \
  --policy.pretrained_name_or_path=x-square-robot/wall-oss-flow \
  --policy.text_loss_weight=0.01 \
  --policy.flow_loss_weight=1.0 \
  --policy.device=cuda \
  --batch_size=1 \
  --steps=20000
```

目标助手轮次（assistant turns）接收下一 token 交叉熵，而 `low_level`
配方流接收连续的流动作监督。一行可以接收任一目标，或同时接收两者。用户提示、图像、本体感觉（proprioception）、动作查询
token 和填充均不计入文本损失。设置 `policy.recipe=null` 可使用 WALL-OSS 原本的仅动作训练路径。

有关标注模式和可用配方，请参见 [语言列与配方](./language_and_recipes)。

### 训练参数[[training-arguments]]

| 参数                           | 描述                                                                                                             |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `--dataset.repo_id`            | 你训练数据集的 Hugging Face Hub 仓库 ID（例如 `lerobot/aloha_sim_insertion_human`）                              |
| `--policy.type`                | 指定使用 WallX 策略架构                                                                                          |
| `--output_dir`                 | 保存训练检查点和日志的本地目录                                                                                   |
| `--job_name`                   | 本次训练运行的名称标识符（用于日志记录/跟踪）                                                                    |
| `--policy.repo_id`             | 训练后模型将推送到的 Hugging Face Hub 仓库 ID                                                                    |
| `--policy.pretrained_path`     | 用于初始化的预训练 WallX 权重路径（官方 WALL-OSS 检查点）                                                        |
| `--policy.prediction_mode`     | 动作预测策略（strategy）：`diffusion` 或 `fast` - `diffusion` 使用迭代去噪生成动作，`fast` 则使用下一 token 预测 |
| `--policy.attn_implementation` | 注意力实现后端 - `eager` 使用标准 PyTorch 注意力（替代方案包括 `flash_attention_2` 或 `sdpa`）                   |
| `--steps`                      | 要运行的训练总步数                                                                                               |
| `--policy.device`              | 用于训练的设备（`cuda` 表示 GPU，`cpu` 表示 CPU）                                                                |
| `--batch_size`                 | 每个训练批次的样本数                                                                                             |

语言训练使用 `policy.text_loss_weight`（默认 `0.01`）、
`policy.flow_loss_weight`（默认 `1.0`）和 `policy.tokenizer_max_length`
（默认 `768`）。`policy.recipe_path` 可选择替换内置配方。
