# 自带硬件[[bring-your-own-hardware]]

本教程将说明如何将自己的机器人设计集成到 LeRobot 生态系统中，并让它使用我们的所有工具（数据采集、控制流水线、策略（policy）训练与推理）。

为此，我们在 LeRobot 中提供了 [`Robot`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/robots/robot.py) 基类，它规定了用于物理机器人集成的标准接口。下面看看如何实现它。

## 前提条件[[prerequisites]]

- 你自己的机器人，它提供通信接口（例如串口、CAN、TCP）
- 一种以编程方式读取传感器数据并发送电机命令的方法，例如厂商的 SDK 或 API，或你自己的协议实现。
- 你的环境中已安装 LeRobot。请遵循我们的[安装指南](./installation)。

## 选择你的电机[[choose-your-motors]]

如果你使用的是 Feetech 或 Dynamixel 电机，LeRobot 提供了内置的总线接口：

- [`FeetechMotorsBus`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/motors/feetech/feetech.py) —— 用于控制 Feetech 舵机
- [`DynamixelMotorsBus`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/motors/dynamixel/dynamixel.py) —— 用于控制 Dynamixel 舵机

请参阅 [`MotorsBus`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/motors/motors_bus.py) 抽象类以了解其 API。
有关其使用方式的良好示例，可以查看我们自己的 [SO101 从臂实现](https://github.com/huggingface/lerobot/blob/main/src/lerobot/robots/so_follower/so_follower.py)。

如果兼容，请使用这些接口。否则，你需要寻找或编写一个 Python 接口（本教程不涉及）：

- 寻找现有的 Python SDK（或使用 C/C++ 绑定）
- 或者实现一个基本的通信封装（例如通过 pyserial、socket 或 CANopen）

你并不孤单——许多社区贡献都使用了自定义板卡或固件！

对于 Feetech 和 Dynamixel，我们目前支持以下舵机： - Feetech： - STS 与 SMS 系列（协议 0）：`sts3215`、`sts3250`、`sm8512bl` - SCS 系列（协议 1）：`scs0009` - Dynamixel（仅协议 2.0）：`xl330-m077`、`xl330-m288`、`xl430-w250`、`xm430-w350`、`xm540-w270`、`xc430-w150`

如果你使用的 Feetech 或 Dynamixel 舵机不在上述列表中，可以在 [Feetech 表](https://github.com/huggingface/lerobot/blob/main/src/lerobot/motors/feetech/tables.py) 或 [Dynamixel 表](https://github.com/huggingface/lerobot/blob/main/src/lerobot/motors/dynamixel/tables.py) 中添加它们。根据型号不同，这需要你添加特定于该型号的信息。不过在大多数情况下，需要补充的内容并不多。

在接下来的章节中，我们将在示例中使用 `FeetechMotorsBus` 作为电机接口。如有必要，请将其替换并适配到你的电机。

## 步骤 1：子类化 `Robot` 接口[[step-1-subclass-the-robot-interface]]

你首先需要为你的机器人指定配置类和一个字符串标识符（`name`）。如果你的机器人有希望可以轻松更改的特殊需求，这些应放在这里（例如端口/地址、波特率）。

这里，我们将为我们的机器人默认添加端口名和一个摄像头：

<!-- prettier-ignore-start -->
```python
from dataclasses import dataclass, field

from lerobot.cameras import CameraConfig
from lerobot.cameras.opencv import OpenCVCameraConfig
from lerobot.robots import RobotConfig


@RobotConfig.register_subclass("my_cool_robot")
@dataclass
class MyCoolRobotConfig(RobotConfig):
    port: str
    cameras: dict[str, CameraConfig] = field(
        default_factory={
            "cam_1": OpenCVCameraConfig(
                index_or_path=2,
                fps=30,
                width=480,
                height=640,
            ),
        }
    )
```
<!-- prettier-ignore-end -->

[摄像头教程](./cameras) 可帮助你了解如何检测并添加你的摄像头。

接下来，我们将创建实际的机器人类，它继承自 `Robot`。这个抽象类定义了一个契约，你的机器人必须遵循该契约，才能与其余 LeRobot 工具一起使用。

这里我们将创建一个带有一个摄像头的简单 5 自由度（5-DoF）机器人。它可以是简单的机械臂，但请注意，`Robot` 抽象类并不对你的机器人形态做任何假设。设计新机器人时，你可以尽情发挥想象力！

<!-- prettier-ignore-start -->
```python
from lerobot.cameras import make_cameras_from_configs
from lerobot.motors import Motor, MotorNormMode
from lerobot.motors.feetech import FeetechMotorsBus
from lerobot.robots import Robot

class MyCoolRobot(Robot):
    config_class = MyCoolRobotConfig
    name = "my_cool_robot"

    def __init__(self, config: MyCoolRobotConfig):
        super().__init__(config)
        self.bus = FeetechMotorsBus(
            port=self.config.port,
            motors={
                "joint_1": Motor(1, "sts3250", MotorNormMode.RANGE_M100_100),
                "joint_2": Motor(2, "sts3215", MotorNormMode.RANGE_M100_100),
                "joint_3": Motor(3, "sts3215", MotorNormMode.RANGE_M100_100),
                "joint_4": Motor(4, "sts3215", MotorNormMode.RANGE_M100_100),
                "joint_5": Motor(5, "sts3215", MotorNormMode.RANGE_M100_100),
            },
            calibration=self.calibration,
        )
        self.cameras = make_cameras_from_configs(config.cameras)
```
<!-- prettier-ignore-end -->

## 步骤 2：定义观测和动作特征[[step-2-define-observation-and-action-features]]

这两个属性定义了你的机器人与其使用方工具（例如数据采集或学习流水线）之间的 _接口契约_。

> [!WARNING]
> 请注意，即使机器人尚未连接，这些属性也必须可调用，因此避免依赖运行时硬件状态来定义它们。

### `observation_features`[[observationfeatures]]

该属性应返回一个字典，用于描述机器人传感器输出的结构。其键与 `get_observation()` 返回的内容相匹配，而值描述形状（用于数组/图像）或类型（用于简单值）。

以下是带有一个摄像头的 5-DoF 机械臂的示例：

<!-- prettier-ignore-start -->
```python
@property
def _motors_ft(self) -> dict[str, type]:
    return {
        "joint_1.pos": float,
        "joint_2.pos": float,
        "joint_3.pos": float,
        "joint_4.pos": float,
        "joint_5.pos": float,
    }

@property
def _cameras_ft(self) -> dict[str, tuple]:
    return {
        cam: (self.cameras[cam].height, self.cameras[cam].width, 3) for cam in self.cameras
    }

@property
def observation_features(self) -> dict:
    return {**self._motors_ft, **self._cameras_ft}
```
<!-- prettier-ignore-end -->

在这种情况下，观测（observation）由简单的字典组成，存储每个电机的位置和一张摄像头图像。

### `action_features`[[actionfeatures]]

该属性描述你的机器人通过 `send_action()` 期望接收的命令。同样，键必须与期望的输入格式匹配，值定义每条命令的形状/类型。

这里，我们简单地使用与 `observation_features` 相同的关节本体感受特征（`self._motors_ft`）：发送的动作就是每个电机的目标位置。

<!-- prettier-ignore-start -->
```python
def action_features(self) -> dict:
    return self._motors_ft
```
<!-- prettier-ignore-end -->

## 步骤 3：处理连接与断开[[step-3-handle-connection-and-disconnection]]

这些方法应处理与硬件（例如串口、CAN 接口、USB 设备、摄像头）的通信打开和关闭。

### `is_connected`[[isconnected]]

该属性应仅反映与机器人硬件的通信是否已建立。当该属性为 `True` 时，应能够使用 `get_observation()` 和 `send_action()` 对硬件进行读写。

<!-- prettier-ignore-start -->
```python
@property
def is_connected(self) -> bool:
    return self.bus.is_connected and all(cam.is_connected for cam in self.cameras.values())
```
<!-- prettier-ignore-end -->

### `connect()`[[connect]]

该方法应建立与硬件的通信。此外，如果你的机器人需要校准（calibration）且尚未校准，默认情况下应启动校准流程。如果你的机器人需要某些特定配置，也应在此处调用。

<!-- prettier-ignore-start -->
```python
def connect(self, calibrate: bool = True) -> None:
    self.bus.connect()
    if not self.is_calibrated and calibrate:
        self.calibrate()

    for cam in self.cameras.values():
        cam.connect()

    self.configure()
```
<!-- prettier-ignore-end -->

### `disconnect()`[[disconnect]]

该方法应优雅地终止与硬件的通信：释放任何相关资源（线程或进程）、关闭端口等。

在这里，我们已经在 `MotorsBus` 和 `Camera` 类中处理了这一点，因此只需调用它们各自的 `disconnect()` 方法：

<!-- prettier-ignore-start -->
```python
def disconnect(self) -> None:
    self.bus.disconnect()
    for cam in self.cameras.values():
        cam.disconnect()
```
<!-- prettier-ignore-end -->

## 步骤 4：支持校准与配置[[step-4-support-calibration-and-configuration]]

LeRobot 支持自动保存和加载校准（calibration）数据。这对于关节偏移、零位或传感器对齐很有用。

> 请注意，根据你的硬件不同，这可能不适用。如果是这种情况，你可以直接将这些方法留作空操作（no-op）：

<!-- prettier-ignore-start -->
```python
@property
def is_calibrated(self) -> bool:
    return True

def calibrate(self) -> None:
    pass
```
<!-- prettier-ignore-end -->

### `is_calibrated`[[iscalibrated]]

这应反映你的机器人是否已加载所需的校准。

<!-- prettier-ignore-start -->
```python
@property
def is_calibrated(self) -> bool:
    return self.bus.is_calibrated
```
<!-- prettier-ignore-end -->

### `calibrate()`[[calibrate]]

校准的目标有两个：

- 了解每个电机的物理运动范围，以便只在该范围内发送命令。
- 将原始电机位置归一化为合理的连续值（例如百分比、度数），而不是依赖于所用特定电机的任意离散值，因为这些值无法在其他地方复现。

它应实现校准逻辑（如果相关）并更新 `self.calibration` 字典。如果你使用的是 Feetech 或 Dynamixel 电机，我们的总线接口已经包含有助于完成此操作的方法。

<!-- prettier-ignore-start -->
```python
def calibrate(self) -> None:
    self.bus.disable_torque()
    for motor in self.bus.motors:
        self.bus.write("Operating_Mode", motor, OperatingMode.POSITION.value)

    input(f"Move {self} to the middle of its range of motion and press ENTER....")
    homing_offsets = self.bus.set_half_turn_homings()

    print(
        "Move all joints sequentially through their entire ranges "
        "of motion.\nRecording positions. Press ENTER to stop..."
    )
    range_mins, range_maxes = self.bus.record_ranges_of_motion()

    self.calibration = {}
    for motor, m in self.bus.motors.items():
        self.calibration[motor] = MotorCalibration(
            id=m.id,
            drive_mode=0,
            homing_offset=homing_offsets[motor],
            range_min=range_mins[motor],
            range_max=range_maxes[motor],
        )

    self.bus.write_calibration(self.calibration)
    self._save_calibration()
    print("Calibration saved to", self.calibration_fpath)
```
<!-- prettier-ignore-end -->

### `configure()`[[configure]]

使用该方法设置硬件的任何配置（舵机控制模式、控制器增益等）。这通常应在连接时运行，并且应是幂等的。

<!-- prettier-ignore-start -->
```python
def configure(self) -> None:
    with self.bus.torque_disabled():
        self.bus.configure_motors()
        for motor in self.bus.motors:
            self.bus.write("Operating_Mode", motor, OperatingMode.POSITION.value)
            self.bus.write("P_Coefficient", motor, 16)
            self.bus.write("I_Coefficient", motor, 0)
            self.bus.write("D_Coefficient", motor, 32)
```
<!-- prettier-ignore-end -->

## 步骤 5：实现传感器读取与动作发送[[step-5-implement-sensors-reading-and-action-sending]]

这些是最重要的运行时函数：核心 I/O 循环。

### `get_observation()`[[getobservation]]

返回来自机器人的传感器值字典。这些通常包括电机状态、摄像头帧（frame）、各种传感器等。在 LeRobot 框架中，这些观测（observation）将被馈送给策略（policy），以预测要采取的动作。字典的键和结构必须与 `observation_features` 匹配。

<!-- prettier-ignore-start -->
```python
def get_observation(self) -> dict[str, Any]:
    if not self.is_connected:
        raise ConnectionError(f"{self} is not connected.")

    # 读取机械臂位置
    obs_dict = self.bus.sync_read("Present_Position")
    obs_dict = {f"{motor}.pos": val for motor, val in obs_dict.items()}

    # 从摄像头捕获图像
    for cam_key, cam in self.cameras.items():
        obs_dict[cam_key] = cam.async_read()

    return obs_dict
```
<!-- prettier-ignore-end -->

### `send_action()`[[sendaction]]

接收一个与 `action_features` 匹配的字典，并将其发送到你的硬件。你可以添加安全限制（裁剪、平滑），并返回实际发送的内容。

为简单起见，我们在此示例中不会对动作做任何修改。

<!-- prettier-ignore-start -->
```python
def send_action(self, action: dict[str, Any]) -> dict[str, Any]:
    goal_pos = {key.removesuffix(".pos"): val for key, val in action.items()}

    # 向机械臂发送目标位置
    self.bus.sync_write("Goal_Position", goal_pos)

    return action
```
<!-- prettier-ignore-end -->

## 添加遥操作器（Teleoperator）[[adding-a-teleoperator]]

为了实现遥操作（teleoperation）设备，我们还提供了 [`Teleoperator`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/teleoperators/teleoperator.py) 基类。该类与 `Robot` 基类非常相似，同样不对形态做任何假设。

主要区别在于 I/O 函数：遥操作器允许你通过 `get_action` 产生动作，并可通过 `send_feedback` 接收反馈动作。反馈可以是遥操作设备上任何可控的内容，用于帮助控制者理解所发送动作的后果。例如，主臂（leader arm）上的运动/力反馈，或游戏手柄控制器上的振动。要实现遥操作器，你可以遵循本教程，并针对这两个方法进行调整。

## 使用你自己的 `LeRobot` 设备 🔌[[using-your-own-lerobot-devices-]]

你可以通过创建一个独立的、可安装的 Python 包，轻松地用自己的自定义硬件（无论是摄像头、机器人还是遥操作设备）扩展 `lerobot`。如果你遵循一些简单的约定，`lerobot` 命令行工具（如 `lerobot-teleop` 和 `lerobot-record`）将**自动发现并集成你的扩展**，而无需对 `lerobot` 源代码进行任何更改。

本指南概述了你的插件必须遵循的约定。

### 4 个核心约定[[the-4-core-conventions]]

为确保你的自定义设备可被发现，你必须遵守以下四条规则。

#### 1\. 创建具有特定前缀的可安装包[[1-create-an-installable-package-with-a-specific-prefix]]

你的项目必须是一个标准的、可安装的 Python 包。关键的是，你的包名（如 `pyproject.toml` 或 `setup.py` 中所定义）必须以下列前缀之一开头：

- `lerobot_robot_` 用于机器人。
- `lerobot_camera_` 用于摄像头。
- `lerobot_teleoperator_` 用于遥操作设备。
- `lerobot_strategy_` 用于 `lerobot-rollout` 策略（strategy）（参见 [自带策略](./inference#bring-your-own-strategy)）。

这个前缀系统正是 `lerobot` 在 Python 环境中自动找到你的插件的方式。

#### 2\. 遵循 `SomethingConfig`/`Something` 命名模式[[2-follow-the-somethingconfigsomething-naming-pattern]]

你的设备实现类必须根据其配置类命名，只需去掉 `Config` 后缀即可。

- **配置类：** `MyAwesomeTeleopConfig`
- **设备类：** `MyAwesomeTeleop`

#### 3\. 将文件放在可预测的结构中[[3-place-your-files-in-a-predictable-structure]]

设备类（`MyAwesomeTeleop`）必须位于相对于其配置类（`MyAwesomeTeleopConfig`）的可预测模块中。`lerobot` 将自动在以下位置搜索：

- 在与配置类**相同的模块**中。
- 在**以设备命名的子模块**中（例如 `my_awesome_teleop.py`）。

推荐且最简单的结构是将它们放在同一目录下单独的、命名清晰的文件中。

#### 4\. 在 `__init__.py` 中暴露类[[4-expose-classes-in-initpy]]

你的包的 `__init__.py` 文件应导入并暴露配置类和设备类，使它们易于访问。

### 综合起来：一个完整示例[[putting-it-all-together-a-complete-example]]

让我们创建一个名为 `my_awesome_teleop` 的新遥操作器。

#### 目录结构[[directory-structure]]

项目文件夹应如下所示。包名 `lerobot_teleoperator_my_awesome_teleop` 遵循**约定 \#1**。

```
lerobot_teleoperator_my_awesome_teleop/
├── pyproject.toml # （或 setup.py）将 lerobot 列为依赖项
└── lerobot_teleoperator_my_awesome_teleop/
    ├── __init__.py
    ├── config_my_awesome_teleop.py
    └── my_awesome_teleop.py
```

#### 文件内容[[file-contents]]

- **`config_my_awesome_teleop.py`**：定义配置类。注意 `Config` 后缀（**约定 \#2**）。

  ```python
  from dataclasses import dataclass

  from lerobot.teleoperators.config import TeleoperatorConfig

  @TeleoperatorConfig.register_subclass("my_awesome_teleop")
  @dataclass
  class MyAwesomeTeleopConfig(TeleoperatorConfig):
      # 在此填写你的配置字段
      port: str = "192.168.1.1"
  ```

- **`my_awesome_teleop.py`**：实现设备。类名 `MyAwesomeTeleop` 与其配置类名匹配（**约定 \#2**）。此文件结构遵循**约定 \#3**。

  ```python
  from lerobot.teleoperators.teleoperator import Teleoperator

  from .config_my_awesome_teleop import MyAwesomeTeleopConfig

  class MyAwesomeTeleop(Teleoperator):
      config_class = MyAwesomeTeleopConfig
      name = "my_awesome_teleop"

      def __init__(self, config: MyAwesomeTeleopConfig):
          super().__init__(config)
          self.config = config

      # 你的设备逻辑（例如 connect）放在这里
  ```

- **`__init__.py`**：暴露关键类（**约定 \#4**）。

  ```python
  from .config_my_awesome_teleop import MyAwesomeTeleopConfig
  from .my_awesome_teleop import MyAwesomeTeleop
  ```

### 安装与使用[[installation-and-usage]]

1.  **在你的 Python 环境中安装新插件。** 你可以使用 `pip` 的可编辑模式从本地安装插件包，或从 PyPi 安装。

    ```bash
    # 本地
    # 导航到你的插件根目录并安装它
    cd lerobot_teleoperator_my_awesome_teleop
    pip install -e .

    # 从 PyPi 安装
    pip install lerobot_teleoperator_my_awesome_teleop
    ```

2.  **直接从命令行使用它。** 现在，你可以通过引用其类型来使用自定义设备。

    ```bash
    lerobot-teleoperate --teleop.type=my_awesome_teleop \
    # 其他参数
    ```

就是这样！你的自定义设备现在已完全集成。
