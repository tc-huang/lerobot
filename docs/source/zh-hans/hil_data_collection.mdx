# 人在回路数据采集[[human-in-the-loop-data-collection]]

人在回路（Human-In-the-Loop，HIL）数据采集让你可以在真实机器人上部署训练好的策略（policy），并由人类操作员在需要时监控和干预，从而改进该策略。干预数据（恢复动作和纠正）会与自主执行片段一起记录，生成更丰富的训练数据集，教会策略如何处理失败。

---

## 为什么需要人在回路？[[why-human-in-the-loop]]

标准行为克隆（behavioral cloning）仅在成功演示上训练策略（policy）。部署期间，小错误可能会不断累积，并将机器人推入训练中从未见过的状态（分布偏移，distribution shift）。HIL 数据采集通过以下方式解决这一问题：

- 在真实机器人上运行训练好的策略
- 在机器人即将失败时由人类进行干预
- 将人类的恢复与纠正记录为训练数据
- 在组合数据集上微调策略

这会生成一个策略（policy），它不仅知道如何执行任务，还知道在出现问题时如何恢复。

---

## 工作原理[[how-it-works]]

在一次 HIL 会话中，人类操作员会在每个片段（episode）内遵循以下循环：

1. **观察**策略自主运行
2. 在即将失败时**暂停**，机器人保持其位置
3. **接管控制**，遥操作（teleoperation）机器人回到良好状态（恢复），然后纠正行为
4. **将控制权交还给策略**，策略恢复自主执行
5. 在片段期间按需重复步骤 2–4 任意多次
6. 任务完成后**结束片段**，保存并继续下一个 rollout

自主片段和人类控制的片段都会被记录。策略（policy）与人类可以在单个片段内多次交替控制，并且每次交接后片段都会从当前状态继续（不会仅因发生干预而需要重置）。这会将自主执行、恢复和纠正捕获为一条连续轨迹。采集完成后，使用组合数据集（原始演示 + HIL 数据）微调策略。

这个过程可以迭代重复：部署、采集、微调、重复。每一轮都针对当前策略（policy）的失败模式。

```
┌─────────────────────────────────────────────────────────────────────────┐
│  Policy v0 (trained on demos)                                           │
│       ↓                                                                 │
│  HIL Collection (target current failure modes) → Fine-tune → Policy v1  │
│       ↓                                                                 │
│  HIL Collection (target new failure modes) → Fine-tune → Policy v2      │
│       ↓                                                                 │
│  ... (repeat until satisfactory performance)                            │
└─────────────────────────────────────────────────────────────────────────┘
```

## 硬件要求[[hardware-requirements]]

### 遥操作器要求[[teleoperator-requirements]]

`lerobot-rollout --strategy.type=dagger` 模式需要**带主动电机的遥操作器（teleoperator）**，它们能够：

- 以编程方式启用/禁用扭矩
- 移动到目标位置（在暂停时镜像机器人状态）

**兼容的遥操作器：**

- `bi_openarm_mini` - 双臂 OpenArm Mini
- `so_leader` - SO100 / SO101 主臂
- `bi_so_leader` - 双臂 SO100 / SO101 主臂

> [!IMPORTANT]
> 提供的命令默认使用 `bi_openarm_follower` + `bi_openarm_mini`。
> `so_follower` + `so_leader` 配置也已注册，并可通过 CLI 标志使用。

## 脚本[[script]]

使用 `lerobot-rollout` 和 `--strategy.type=dagger` 进行 HIL 数据采集。使用 `--inference.type=sync|rtc` 选择推理后端：

| 模式                                | 标志                   | 模型                  |
| ----------------------------------- | ---------------------- | --------------------- |
| 标准（默认）                        | _（无需标志）_         | ACT、Diffusion Policy |
| 实时分块（Real-Time Chunking，RTC） | `--inference.type=rtc` | Pi0、Pi0.5、SmolVLA   |

## 分步指南[[step-by-step-guide]]

### 步骤 1：预训练基础策略[[step-1-pre-train-a-base-policy]]

首先，在你的演示数据集上训练一个策略（policy）：

```bash
python src/lerobot/scripts/lerobot_train.py \
    --dataset.repo_id=your-username/demo-dataset \
    --policy.type=pi0 \
    --output_dir=outputs/pretrain \
    --batch_size=32 \
    --steps=50000
```

### 步骤 2：采集 HIL 数据[[step-2-collect-hil-data]]

**标准推理（ACT、Diffusion Policy）：**

```bash
lerobot-rollout --strategy.type=dagger \
    --robot.type=bi_openarm_follower \
    --robot.left_arm_config.port=can1 \
    --robot.left_arm_config.side=left \
    --robot.right_arm_config.port=can0 \
    --robot.right_arm_config.side=right \
    --robot.cameras='{left_wrist: {type: opencv, index_or_path: "/dev/video0", width: 1280, height: 720, fps: 30}, right_wrist: {type: opencv, index_or_path: "/dev/video4", width: 1280, height: 720, fps: 30}, base: {type: opencv, index_or_path: "/dev/video2", width: 640, height: 480, fps: 30}}' \
    --teleop.type=bi_openarm_mini \
    --teleop.left_arm_config.port=/dev/ttyACM0 \
    --teleop.right_arm_config.port=/dev/ttyACM1 \
    --policy.path=outputs/pretrain/checkpoints/last/pretrained_model \
    --dataset.repo_id=your-username/rollout_hil_dataset \
    --dataset.single_task="Fold the T-shirt properly" \
    --dataset.fps=30 \
    --strategy.num_episodes=50 \
    --interpolation_multiplier=2
```

使用 `--interpolation_multiplier=N` 时，机器人会针对每个策略（policy）动作接收 `N` 条插值命令（控制以 `fps × N` Hz 运行），而策略推理和数据集记录仍保持 `--fps`，因此记录的数据集与其声明的 FPS 匹配。

**对大型模型（Pi0、Pi0.5、SmolVLA）使用 RTC 时：**

对于推理延迟较高的模型，请启用 RTC 以实现平滑执行：

```bash
lerobot-rollout --strategy.type=dagger \
    --inference.type=rtc \
    --inference.rtc.execution_horizon=20 \
    --inference.rtc.max_guidance_weight=5.0 \
    --inference.rtc.prefix_attention_schedule=LINEAR \
    --robot.type=bi_openarm_follower \
    --robot.left_arm_config.port=can1 \
    --robot.left_arm_config.side=left \
    --robot.right_arm_config.port=can0 \
    --robot.right_arm_config.side=right \
    --robot.cameras='{left_wrist: {type: opencv, index_or_path: "/dev/video0", width: 1280, height: 720, fps: 30}, right_wrist: {type: opencv, index_or_path: "/dev/video4", width: 1280, height: 720, fps: 30}, base: {type: opencv, index_or_path: "/dev/video2", width: 640, height: 480, fps: 30}}' \
    --teleop.type=bi_openarm_mini \
    --teleop.left_arm_config.port=/dev/ttyACM0 \
    --teleop.right_arm_config.port=/dev/ttyACM1 \
    --policy.path=outputs/pretrain/checkpoints/last/pretrained_model \
    --dataset.repo_id=your-username/rollout_hil_rtc_dataset \
    --dataset.single_task="Fold the T-shirt properly" \
    --dataset.fps=30 \
    --strategy.num_episodes=50 \
    --interpolation_multiplier=3
```

**控制方式（概念性）：**

交互模型如下：

- **暂停输入**：暂停策略（policy）的自主执行
- **接管输入**：将控制权转移给人类操作员并记录干预数据
- **返回策略输入**：将控制权交还给策略并继续同一片段
- **片段控制输入**：按需保存/重新录制/停止/重置

确切的按键/踏板绑定可能因脚本和硬件集成而异。请以每个脚本打印出的控制说明为准，确定你所用设备上的具体映射。

**HIL 协议：**

1. 观察策略（policy）自主运行（遥操作空闲/自由）
2. 当你看到即将失败时，触发**暂停输入**
   - 策略停止
   - 遥操作器移动到与机器人位置匹配的位置（启用扭矩）
   - 暂停期间不记录任何帧（frame）
3. 触发**接管输入**以取得控制
   - 遥操作器扭矩禁用，可自由移动
   - **恢复**：遥操作机器人回到良好状态
   - **纠正**：纠正行为
   - 所有移动都会被记录
4. 触发**返回策略输入**
   - 策略从当前状态恢复自主执行
   - 你可以随时再次干预（重复步骤 2–4）
5. 任务完成（或达到片段时间限制）时结束并保存片段
6. **重置**：遥操作器移动到机器人位置，你可以将机器人移动到起始位置
7. 开始下一个片段

**脚踏板设置（Linux）：**

如果使用 USB 脚踏板（PCsensor FootSwitch），请确保可访问：

```bash
sudo setfacl -m u:$USER:rw /dev/input/by-id/usb-PCsensor_FootSwitch-event-kbd
```

### 步骤 3：微调策略[[step-3-fine-tune-the-policy]]

在**组合**数据集上微调（将 `demo-dataset` + `hil-dataset` 合并在一起）：

```bash
python src/lerobot/scripts/lerobot_train.py \
    --dataset.repo_id=your-username/hil-dataset \
    --policy.type=pi0 \
    --policy.pretrained_path=outputs/pretrain/checkpoints/last/pretrained_model \
    --output_dir=outputs/hil_finetune \
    --steps=20000
```

然后部署微调后的策略，并从步骤 2 开始重复，以针对其剩余的失败模式。

## 有效进行 HIL 采集的技巧[[tips-for-effective-hil-collection]]

### 何时干预[[when-to-intervene]]

当你看到以下情况时进行干预：

- 机器人即将犯下不可逆的错误
- 机器人犹豫或表现出不确定行为
- 机器人偏离预期轨迹

### 恢复：遥操作回到良好状态[[recovery-teleoperating-back-to-a-good-state]]

在恢复期间，遥操作机器人回到满足以下条件的状态：

- 机器人处于熟悉的、分布内配置
- 当前子任务仍可完成
- 恢复轨迹本身就是有信息量的训练数据

### 纠正的质量[[quality-of-corrections]]

在纠正期间：

- 提供**自信、干净**的轨迹
- 完整完成当前子任务
- 不要过度纠正或添加不必要的移动

## 相关工作[[related-work]]

这种 HIL 数据采集方法建立在交互式模仿学习的理念之上：

- **DAgger**（Ross 等，2011）引入了核心思想：不要仅在专家演示上训练，而是针对 _学习者_ 访问到的状态向专家查询纠正。它通过迭代采集同策略数据（on-policy data），打破了标准行为克隆的复合误差循环。

- **HG-DAgger**（Kelly 等，2019）让这种方法适用于机器人领域：由人类专家监控机器人，仅在需要时进行干预，而不是为每个状态打标签。自主控制与人类控制之间的门控，正是此处脚本中使用的 暂停 → 接管 → 返回策略循环。

- **RaC**（Hu 等，2025）通过将干预明确分解为**恢复**（遥操作回到良好状态）和**纠正**（从该状态示范正确行为），将此循环扩展到长时程任务。这种分解正是 `lerobot-rollout` 中 DAgger 策略（strategy）所遵循的协议。

- **π0.6/RECAP**（Physical Intelligence，2025）在 VLA 模型上大规模应用相同的迭代采集与微调循环，表明即使大型预训练策略（policy）也能从其自身失败模式上有针对性的人类纠正中获得显著收益。π0.6 使用 RECAP 训练。
