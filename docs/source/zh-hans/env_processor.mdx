# 环境处理器[[environment-processors]]

环境处理器（environment processor）是 LeRobot 数据处理架构中的关键层，负责处理**环境特定**的变换，与策略（policy）特定的处理分开。这种关注点分离（separation of concerns）可实现更清晰的代码、更好的模块化，以及更轻松地针对不同环境和策略进行实验。

## 为什么需要环境处理器？[[why-environment-processors]]

在处理不同的机器人环境（LIBERO、MetaWorld、Aloha 等）时，每个环境通常都有独特的数据格式、坐标系和约定，这些内容需要在策略处理**之前**进行标准化。如果没有环境处理器，这些变换将会：

1. **硬编码在环境代码中** - 难以尝试不同的状态表示
2. **在各策略之间重复** - 每个策略都需要处理环境特定的怪异之处
3. **与策略逻辑混杂** - 违反关注点分离，并使调试更困难

环境处理器通过在原始环境观测（observation）和策略输入之间提供**专用处理层**来解决此问题。

## 处理流水线[[the-processing-pipeline]]

以下是评估期间数据流经完整处理流水线的方式：

```python
# 在 lerobot_eval.py 的 rollout() 函数中：

# 1. 原始环境观测（numpy 数组，各种格式）
raw_observation = env.step(action)

# 2. 将 numpy 转换为 torch，归一化图像至 [0,1]
observation = preprocess_observation(raw_observation)

# 3. 添加任务元数据（用于多任务环境）
observation = add_envs_task(env, observation)

# 4. 环境特定预处理（新增！）
#    - 展平机器人状态
#    - 旋转图像以匹配数据集约定
#    - 处理环境特定的坐标系统
observation = env_preprocessor(observation)

# 5. 策略特定预处理
#    - 使用数据集统计信息进行归一化
#    - 添加批次维度
#    - 移动到 GPU
#    - 对语言指令进行分词
observation = preprocessor(observation)

# 6. 策略推理
action = policy.select_action(observation)

# 7. 策略特定后处理
#    - 反归一化动作
#    - 移除批次维度
action = postprocessor(action)

# 8. 环境特定后处理（新增！）
#    - 如有需要，转换动作格式
#    - 应用环境特定约束
action_transition = {"action": action}
action_transition = env_postprocessor(action_transition)
action = action_transition["action"]

# 9. 在环境中执行
env.step(action)
```

## 优势[[the-benefits]]

### 1. **关注点分离**[[1-separation-of-concerns]]

环境处理器处理**环境数据格式**特定的变换，而策略处理器处理**模型需求**特定的变换。

```python
# ❌ 之前：关注点混杂
class LiberoVLAPolicy:
    def preprocess(self, obs):
        # 环境特定：展平机器人状态（不应放在策略中！）
        state = self._flatten_robot_state(obs["robot_state"])
        # 策略特定：使用数据集统计信息归一化
        state = self.normalizer(state)
        return state

# ✅ 之后：清晰分离
# 环境处理器：处理 LIBERO 的嵌套机器人状态
env_preprocessor = LiberoProcessorStep()  # 展平 robot_state

# 策略处理器：处理模型需求
policy_preprocessor = NormalizerProcessorStep(stats=dataset_stats)
```

### 2. **灵活性与可复用性**[[2-flexibility-and-reusability]]

同一个策略可以搭配不同环境处理器使用，同一个环境处理器也可以搭配不同策略使用：

```python
# 将 SmolVLA 策略与 LIBERO 环境一起使用
libero_preprocessor, libero_postprocessor = make_env_pre_post_processors(
    env_cfg=libero_cfg,
    policy_cfg=smolvla_cfg,
)
smolvla_preprocessor, smolvla_postprocessor = make_pre_post_processors(smolvla_cfg)

# 或者将 ACT 策略与同一个 LIBERO 环境一起使用
libero_preprocessor, libero_postprocessor = make_env_pre_post_processors(
    env_cfg=libero_cfg,
    policy_cfg=act_cfg,
)
act_preprocessor, act_postprocessor = make_pre_post_processors(act_cfg)
```

### 3. **更轻松的试验**[[3-easier-experimentation]]

想为 LIBERO 尝试不同的状态表示？只需创建一个新处理器：

```python
# 原始：8D 状态（pos + quat→axisangle + gripper）
@ProcessorStepRegistry.register("libero_processor")
class LiberoProcessorStep(ObservationProcessorStep):
    def _process_observation(self, obs):
        eef_pos = robot_state["eef"]["pos"]          # 3D
        eef_axisangle = quat2axisangle(quat)         # 3D
        gripper = robot_state["gripper"]["qpos"]     # 2D
        state = torch.cat([eef_pos, eef_axisangle, gripper], dim=-1)  # 8D
        return state

# 试验：添加速度以实现更好的控制
@ProcessorStepRegistry.register("libero_velocity_processor")
class LiberoVelocityProcessorStep(ObservationProcessorStep):
    def _process_observation(self, obs):
        # 包含速度以形成 14D 状态
        eef_pos = robot_state["eef"]["pos"]          # 3D
        eef_axisangle = quat2axisangle(quat)         # 3D
        eef_vel = robot_state["eef"]["vel"]          # 3D  (新增)
        gripper_pos = robot_state["gripper"]["qpos"] # 2D
        gripper_vel = robot_state["gripper"]["qvel"] # 3D  (新增)
        state = torch.cat([eef_pos, eef_axisangle, eef_vel,
                          gripper_pos, gripper_vel], dim=-1)  # 14D
        return state
```

## 使用环境处理器[[using-environment-processors]]

### 工厂函数[[factory-function]]

`make_env_pre_post_processors` 函数遵循与策略的 `make_pre_post_processors` 相同的模式：

```python
from lerobot.envs import make_env_pre_post_processors, PushtEnv
from lerobot.envs.configs import LiberoEnv

# 对于 LIBERO：在预处理中返回 LiberoProcessorStep
libero_cfg = LiberoEnv(task="libero_spatial", camera_name=["agentview"])
env_preprocessor, env_postprocessor = make_env_pre_post_processors(libero_cfg)

# 对于其他环境：返回恒等处理器（空操作）
pusht_cfg = PushtEnv()
env_preprocessor, env_postprocessor = make_env_pre_post_processors(pusht_cfg)
```

### `envs/factory.py` 中的实现[[implementation-in-envsfactorypy]]

```python
def make_env_pre_post_processors(
    env_cfg: EnvConfig,
) -> tuple[
    PolicyProcessorPipeline[dict[str, Any], dict[str, Any]],
    PolicyProcessorPipeline[dict[str, Any], dict[str, Any]],
]:
    """
    为环境观测创建预处理器和后处理器流水线。

    参数：
        env_cfg: 环境的配置。

    返回：
        一个元组，包含：
            - preprocessor：处理环境观测的流水线
            - postprocessor：处理环境输出的流水线
    """
    # 对于 LIBERO 环境，将 LiberoProcessorStep 添加到预处理器
    if isinstance(env_cfg, LiberoEnv) or "libero" in env_cfg.type:
        preprocessor = PolicyProcessorPipeline(steps=[LiberoProcessorStep()])
    else:
        # 对于所有其他环境，返回恒等预处理器
        preprocessor = PolicyProcessorPipeline(steps=[])

    # 后处理器目前对所有环境都是恒等的
    # 未来：可以添加环境特定的动作变换
    postprocessor = PolicyProcessorPipeline(steps=[])

    return preprocessor, postprocessor
```

### 在评估中的集成[[integration-in-evaluation]]

在 `lerobot_eval.py` 中，环境处理器只创建一次，并在整个过程中使用：

```python
def eval_main(cfg: EvalPipelineConfig):
    # 创建环境
    envs = make_env(cfg.env, n_envs=cfg.eval.batch_size)

    # 创建策略

    # 创建策略处理器
    preprocessor, postprocessor = make_pre_post_processors(
        policy_cfg=cfg.policy,
        pretrained_path=cfg.policy.pretrained_path,

    # 创建环境处理器（新增！）
    env_preprocessor, env_postprocessor = make_env_pre_post_processors(env_cfg=cfg.env)

    # 使用两种处理器类型运行评估
    eval_policy_all(
        envs=envs,
        policy=policy,
        env_preprocessor=env_preprocessor,      # 环境特定
        env_postprocessor=env_postprocessor,    # 环境特定
        preprocessor=preprocessor,              # 策略特定
        postprocessor=postprocessor,            # 策略特定
        n_episodes=cfg.eval.n_episodes,
    )
```

## 示例：LIBERO 环境处理器[[example-libero-environment-processor]]

`LiberoProcessorStep` 展示了一个真实世界的环境处理器：

```python
from lerobot.processor import ObservationProcessorStep

@dataclass
@ProcessorStepRegistry.register(name="libero_processor")
class LiberoProcessorStep(ObservationProcessorStep):
    """
    将 LIBERO 观测处理为 LeRobot 格式。

    **状态处理：**
    - 提取末端执行器位置（3D）
    - 将四元数转换为轴角表示（3D）
    - 提取夹爪关节位置（2D）
    - 拼接为 8D 状态向量

    **图像处理：**
    - 将图像旋转 180° 以匹配 HuggingFaceVLA/libero 约定
    """

    def _process_observation(self, observation):
        processed_obs = observation.copy()

        # 处理图像：按相机约定翻转 180°
        for key in list(processed_obs.keys()):
            if key.startswith("observation.images."):
                img = processed_obs[key]
                img = torch.flip(img, dims=[2, 3])  # 翻转 H 和 W
                processed_obs[key] = img

        # 处理 robot_state：展平为 8D 向量
        if "observation.robot_state" in processed_obs:
            robot_state = processed_obs.pop("observation.robot_state")

            eef_pos = robot_state["eef"]["pos"]           # (B, 3)
            eef_quat = robot_state["eef"]["quat"]         # (B, 4)
            gripper_qpos = robot_state["gripper"]["qpos"] # (B, 2)

            # 将四元数转换为轴角
            eef_axisangle = self._quat2axisangle(eef_quat)  # (B, 3)

            # 拼接为单个状态向量
            state = torch.cat((eef_pos, eef_axisangle, gripper_qpos), dim=-1)
            state = state.float()

            processed_obs["observation.state"] = state

        return processed_obs
```

### 为什么需要这些变换？[[why-these-transformations]]

1. **图像旋转**：HuggingFaceVLA/libero 数据集的图像相对于原始 LIBERO 模拟器旋转了 180°。处理器处理这种约定不匹配，使在该数据集上训练的策略能够无缝工作。

2. **状态展平**：原始 LIBERO 环境公开嵌套字典，其中包含所有可用状态信息（位置、四元数、速度、矩阵表示等）。处理器会：
   - 选择相关组件（pos、quat、gripper）
   - 将四元数转换为轴角（更适合学习）
   - 展平为策略期望的单个 8D 向量

3. **灵活性**：环境仍然公开**所有**原始数据。如果你想尝试不同的状态表示（例如，包含速度、使用矩阵表示而不是轴角），可以创建新处理器而无需修改环境代码。

## 为新环境添加环境处理器[[adding-environment-processors-for-new-environments]]

要为新的环境添加环境处理器：

### 1. 创建处理器步骤[[1-create-the-processor-step]]

```python
# 在 src/lerobot/processor/env_processor.py 中

@dataclass
@ProcessorStepRegistry.register(name="myenv_processor")
class MyEnvProcessorStep(ObservationProcessorStep):
    """处理来自 MyEnv 的观测。"""

    def _process_observation(self, observation):
        processed = observation.copy()

        # 你的环境特定变换
        if "myenv.specific.state" in processed:
            state = processed.pop("myenv.specific.state")
            # 转换为标准格式
            processed["observation.state"] = self._transform_state(state)

        return processed
```

### 2. 更新你的 `EnvConfig` 子类[[2-update-your-envconfig-subclass]]

```python
# 在 src/lerobot/envs/factory.py 中

def make_env_pre_post_processors(env_cfg: EnvConfig):
    if isinstance(env_cfg, LiberoEnv) or "libero" in env_cfg.type:
        preprocessor = PolicyProcessorPipeline(steps=[LiberoProcessorStep()])
    elif isinstance(env_cfg, MyEnvConfig) or "myenv" in env_cfg.type:
        preprocessor = PolicyProcessorPipeline(steps=[MyEnvProcessorStep()])
    else:
        preprocessor = PolicyProcessorPipeline(steps=[])

    postprocessor = PolicyProcessorPipeline(steps=[])
    return preprocessor, postprocessor
```

### 3. 在评估中使用[[3-use-in-evaluation]]

无需更改！评估脚本会自动使用合适的处理器：

```bash
lerobot-eval \
    --policy.path=lerobot/my_policy \
    --env.type=myenv \  # 自动使用 MyEnvProcessorStep
    --eval.n_episodes=10
```

## 未来：环境后处理器[[future-environment-postprocessors]]

目前，后处理器对所有环境都是恒等的（空操作）。未来的用例包括：

### 动作空间变换[[action-space-transformations]]

```python
@dataclass
class MyEnvActionPostprocessor(ProcessorStep):
    """将策略动作转换为环境特定格式。"""

    def __call__(self, transition: EnvTransition) -> EnvTransition:
        action = transition["action"]

        # 示例：从笛卡尔空间转换到关节空间
        if self.action_space == "joint":
            action = self.ik_solver(action)

        # 示例：应用环境特定的安全限制
        action = torch.clamp(action, self.min_action, self.max_action)

        transition["action"] = action
        return transition
```

## 最佳实践[[best-practices]]

1. **保持环境处理器简单**：它们应只处理环境特定的数据格式问题，而不是复杂的学习相关变换。

2. **使用策略处理器满足模型需求**：归一化、批处理、设备放置和分词都属于策略处理器的职责。

3. **从环境公开所有数据**：让处理器决定使用什么，而不是在环境中硬编码选择。

4. **记录约定**：清楚记录处理器所处理的任何坐标系约定、相机朝向或数据格式。

5. **独立测试**：环境处理器应能够在不加载完整策略或环境的情况下进行测试。

## 总结[[summary]]

环境处理器在环境特定的数据变换与策略特定的模型需求之间提供了**清晰的分离**。此架构：

- ✅ 支持轻松试验不同的状态表示
- ✅ 允许策略在不同环境之间无缝工作
- ✅ 使环境代码专注于仿真/硬件接口
- ✅ 使处理器流水线更易维护和调试
- ✅ 遵循单一职责原则

关键洞见：**环境定义数据格式，处理器将其标准化，策略消费标准化数据。** 每一层都有清晰、聚焦的职责。
