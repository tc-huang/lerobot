# 重命名映射与空相机[[rename-map-and-empty-cameras]]

当你使用机器人策略（policy）进行训练、评估或录制时，你的**数据集**或**环境**会以一组键（例如 `observation.images.front`、`observation.images.eagle`）提供观测，而你的**策略**期望的是另一组键（例如 `observation.images.image`、`observation.images.image2`）。**重命名映射（rename map）**弥合了这一差距，而无需更改策略或数据源。

> **范围：**重命名映射只重命名**观测**键（图像和状态）。动作键不受影响。

## 为什么观测键并不总是匹配[[why-observation-keys-dont-always-match]]

策略在预训练配置中固化了一组固定的**输入特征名称**。例如：

- [pi0fast-libero](https://huggingface.co/lerobot/pi0fast-libero) 期望 `observation.images.base_0_rgb` 和 `observation.images.left_wrist_0_rgb`。
- [xvla-base](https://huggingface.co/lerobot/xvla-base) 期望 `observation.images.image`、`observation.images.image2` 和 `observation.images.image3`。

你的数据集可能完全使用不同的名称（例如 `observation.images.front`、`observation.images.eagle`、`observation.images.glove`），而你的评估环境可能使用另一组名称。与其编辑策略配置或重命名数据集中的列，不如传入一个**重命名映射**：一个将源键映射到策略期望键的 JSON 字典。重命名发生在预处理器流水线内部，因此策略始终看到其期望的键。

## 使用重命名映射[[using-the-rename-map]]

在命令行中，将映射作为 JSON 字符串传入。约定始终如下：

```
--rename_map='{"source_key": "policy_key", ...}'
```

其中 **source_key** 是数据集或环境提供的键，**policy_key** 是策略期望的键。

只有列出的键会被重命名；其他所有内容都原样通过。条目的顺序无关紧要。

支持的策略：**PI0**、**PI05**、**PI0Fast**、**SmolVLA** 和 **XVLA**。

### 训练[[training]]

假设你在图像位于 `observation.images.front`、`observation.images.eagle` 和 `observation.images.glove` 下的数据集上微调 [lerobot/xvla-base](https://huggingface.co/lerobot/xvla-base)。XVLA 期望 `observation.images.image`、`observation.images.image2` 和 `observation.images.image3`：

```bash
lerobot-train \
  --dataset.repo_id=YOUR_DATASET \
  --output_dir=./outputs/xvla_training \
  --job_name=xvla_training \
  --policy.path="lerobot/xvla-base" \
  --policy.repo_id="HF_USER/xvla-your-robot" \
  --policy.dtype=bfloat16 \
  --policy.action_mode=auto \
  --steps=20000 \
  --policy.device=cuda \
  --policy.freeze_vision_encoder=false \
  --policy.freeze_language_encoder=false \
  --policy.train_policy_transformer=true \
  --policy.train_soft_prompts=true \
  --rename_map='{"observation.images.front": "observation.images.image", "observation.images.eagle": "observation.images.image2", "observation.images.glove": "observation.images.image3"}'
```

### 评估[[evaluation]]

一个期望 `observation.images.base_0_rgb` 和 `observation.images.left_wrist_0_rgb` 的策略（例如 [pi0fast-libero](https://huggingface.co/lerobot/pi0fast-libero)），但 LIBERO 环境返回 `observation.images.image` 和 `observation.images.image2`：

```bash
lerobot-eval \
  --policy.path=lerobot/pi0fast-libero \
  --env.type=libero \
  ... \
  --rename_map='{"observation.images.image": "observation.images.base_0_rgb", "observation.images.image2": "observation.images.left_wrist_0_rgb"}'
```

## 替代方案：直接编辑策略配置[[alternative-edit-the-policy-config-directly]]

如果你始终使用同一个数据集或环境，你可以**编辑策略的 `config.json`**，使其观测键与你的数据源匹配。这样就不需要重命名映射了。

权衡之处在于：修改策略配置会将其绑定到单一数据源。而重命名映射能让同一个策略在多个数据集和环境中使用。

## 空相机：视图数少于策略预期[[empty-cameras-fewer-views-than-the-policy-expects]]

有些策略是为固定数量的图像输入而构建的。如果你的数据集相机数较少，你可以在策略配置中设置 **`empty_cameras`**，而不是修改模型架构。

### 工作原理[[how-it-works]]

设置 `empty_cameras=N` 会向策略配置添加 N 个占位图像特征，命名如下：

```
observation.images.empty_camera_0
observation.images.empty_camera_1
...
```

在运行时，这些键在批次中没有对应的数据。策略会用掩码虚拟张量（masked dummy tensors）填充它们（对于基于 SigLIP 的视觉编码器，用 `-1` 填充，并使用零注意力掩码），因此在训练和推理期间，额外的图像槽位实际上会被忽略。

### 示例[[example]]

XVLA-base 有三个视觉输入，默认 `empty_cameras=0`。你的数据集只有两个相机：

1. 设置 `--policy.empty_cameras=1`。
2. 配置会添加第三个键：`observation.images.empty_camera_0`。
3. 像往常一样为两个真实相机使用重命名映射。
4. 第三个槽位被掩码掉——你的数据集中不需要虚假图像。

## 快速参考[[quick-reference]]

| 目标                           | 操作                                                                    |
| ------------------------------ | ----------------------------------------------------------------------- |
| 数据集键 ≠ 策略键              | `--rename_map='{"dataset_key": "policy_key", ...}'`                     |
| 环境键 ≠ 策略键（评估）        | `--rename_map='{"env_key": "policy_key", ...}'`                         |
| 使用不同键进行 rollout（推理） | `--rename_map='{"source_key": "policy_key", ...}'`。                    |
| 相机数少于策略预期             | `--policy.empty_cameras=N`（由 PI0、PI05、PI0Fast、SmolVLA、XVLA 支持） |
| 避免传入重命名映射             | 编辑策略的 `config.json`，使其键与你的数据源匹配                        |
